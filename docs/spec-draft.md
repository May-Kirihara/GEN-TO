# GEN-TO 仕様草案

- 文書状態: Draft
- 作成日: 2026-08-28
- 対象: 初期仕様検討およびMVP設計

## 1. 製品概要

GEN-TOは、数万枚規模のローカル画像を対象とする高速なデスクトップ画像ビューア兼ファイラーである。

既存のディレクトリ構造を維持したまま通常の画像ファイラーとして利用でき、ユーザーが登録したフォルダでは、タグ、評価、キャプション、EXIF、生成画像メタデータ、AIによる自動解析、自然言語検索などの追加機能を提供する。

主な利用対象は、優先順に以下とする。

1. イラストの閲覧・分類・選別
2. Stable Diffusion等で使用する画像素材および生成画像の管理
3. 写真の閲覧・分類・検索

業務用DAMではなく、個人のヘビーユーザーが快適に使えることを主眼とする。

## 2. 製品原則

- ディレクトリ方式の一般的なファイラーとして扱えること
- 数万枚規模でも閲覧操作が高速であること
- 元画像をアプリ独自領域へ取り込まず、既存の配置を尊重すること
- 元画像へEXIF、IPTC、アプリ固有情報を書き込まないこと
- AI処理によって閲覧やファイル操作を妨げないこと
- AIモデルおよび実行環境をユーザーが自由に選択できること
- データベース障害や別PCへの移行に備え、メタデータを復元可能にすること
- AIが生成した情報と、ユーザーが編集した情報を区別すること

## 3. 対応プラットフォーム

以下のデスクトップOSを対象とする。

- Windows
- Linux
- macOS（可能であれば初期から、難しい場合は後続対応）

具体的な最低対応バージョンは未決定とする。

## 4. フォルダとライブラリ

### 4.1 未登録フォルダ

未登録フォルダも通常の画像ファイラーとして閲覧できる。

- ディレクトリツリーによる移動
- サムネイル一覧
- 単一画像ビューア
- コピー、移動、リネーム、ゴミ箱への移動
- OSのファイルマネージャーで表示
- 外部アプリで開く
- ファイル情報の表示

未登録フォルダでは、永続的なタグ付け、AI解析、意味検索などのライブラリ機能は原則として行わない。一時的な表示用キャッシュは許容する。

### 4.2 登録フォルダ

ユーザーは任意のディレクトリを登録ルートとして追加できる。登録ルートは複数指定できる。

登録フォルダ内では、通常のファイラー機能に加えて以下を有効にする。

- ファイルのインデックス作成
- フォルダ監視と差分スキャン
- タグ、評価、お気に入り、選別状態
- キャプションとユーザーメモ
- EXIF、IPTC、PNGメタデータの読み取り
- AIによるタグおよびキャプション生成
- 全文検索、条件検索、意味検索
- 仮想コレクションおよびスマートコレクション
- 重複候補の検出
- メタデータのバックアップと復元
- Stable Diffusion学習用データのエクスポート

登録ルート同士が包含関係になる場合は、二重インデックスを避けるため警告または登録制限を設ける。

## 5. ファイル管理

### 5.1 基本操作

- コピー
- 移動
- リネーム
- 新規フォルダ作成
- OSのゴミ箱への移動
- 複数選択と一括操作
- ドラッグ＆ドロップ
- パスのコピー
- 外部アプリで開く
- OSのファイルマネージャーで表示

完全削除は通常の削除操作と分離し、明示的な確認を必要とする。

### 5.2 Undo

アプリ内で行った以下の操作は、可能な範囲でUndoに対応する。

- リネーム
- 移動
- ゴミ箱への移動
- タグや評価の変更
- コレクションへの追加・削除

操作後に外部変更が行われたなど、安全に復元できない場合はUndoを拒否し、理由を表示する。

### 5.3 ファイル衝突

コピーまたは移動先に同名ファイルが存在する場合は、以下を選択可能にする。

- 上書き
- スキップ
- 両方を保持
- 新旧画像を比較
- 選択を以降すべてへ適用

衝突画面には、ファイル名だけでなくプレビュー、解像度、ファイル容量、更新日時、ハッシュ一致の有無を表示する。

## 6. 画像の識別と追跡

画像の内容とファイル実体を分けて管理する。

### 6.1 画像内容

- 内容ハッシュ
- タグ
- キャプション
- 評価
- お気に入り
- 選別状態
- AI処理履歴

### 6.2 ファイル実体

- 現在のパス
- ファイル名
- ファイルサイズ
- 更新日時
- 所属する登録ルート
- 利用可能な場合はOS固有のファイル識別子

通常の変更検出にはファイルサイズと更新日時を利用し、必要な場合に内容ハッシュを計算する。内容ハッシュの候補としてBLAKE3を想定するが、技術選定時に確定する。

アプリ内で行われた移動は即座にDBへ反映する。外部で行われた移動やリネームは、OS固有識別子、ファイル属性、内容ハッシュなどを使って再発見する。

## 7. コレクション

コレクションはファイルを移動しない仮想分類とする。

- 1つの画像を複数コレクションへ所属可能
- ユーザー指定の並び順を保持可能
- コレクション単位のエクスポート
- コレクション内だけのメモを将来的に保持可能
- 通常コレクションとスマートコレクションを提供

スマートコレクションは保存された検索条件として扱う。

例:

- 評価4以上かつ特定タグを持つ画像
- 過去30日以内に追加された画像
- キャプションが未作成の画像
- AI処理に失敗した画像
- 除外候補の画像

## 8. 画面構成

基本画面は以下の3ペイン構成を想定する。

1. フォルダツリー、コレクション、保存済み検索
2. サムネイル一覧またはファイル一覧
3. タグ、評価、キャプション、EXIF等の情報パネル

ペインの表示・非表示および幅はユーザーが調整可能とする。

Spaceでクイックプレビュー、Enterまたはダブルクリックで独立したビューアまたは全画面表示へ移行する操作を初期案とする。具体的なキー割り当ては、OS慣習とカスタマイズ性を考慮して決定する。

## 9. 高速画像ビューア

### 9.1 基本機能

- 前後の画像への高速移動
- 画面内フィット
- 幅フィット
- 原寸表示
- マウス位置を中心とするズーム
- パン
- 全画面表示
- 透過画像の背景切り替え
- 画像情報のオーバーレイ
- 次画像の先読み
- 低解像度表示から高解像度表示への段階的更新

MVPで対応する基本画像形式は以下とする。

- JPEG／JPG
- PNG
- WebP
- GIF
- BMP
- TIFF
- AVIF

JPEG XLおよびAPNGは、採用する画像デコード基盤の対応状況を確認した上で、可能であればMVPへ含める。PSDおよびClip Studio Paint形式はMVPの対象外とする。

GIF、WebP等のアニメーション画像は、サムネイル一覧では原則として静止画を表示し、単一画像ビューアでは再生可能とする。具体的な再生操作とAPNG対応範囲は今後決定する。

RAW、HEIF／HEIC、OpenEXR、HDR画像、PDF、PSD、Clip Studio Paint形式はMVP後の対応候補とする。PSDおよびClip Studio Paint形式へ対応する場合も、初期段階では完全なレイヤー解析ではなく、埋め込み統合プレビューの表示を優先する。

### 9.2 選別操作

画像の高速な選別を優先機能とする。

画像は以下の独立した属性を持つ。

- 星評価: 0～5
- 選別状態: 未選別、採用、除外
- お気に入り: ON/OFF
- 任意タグ

除外は削除と区別する。除外画像は後からまとめて確認し、移動またはゴミ箱送りを実行できる。

評価や採否を入力した後、自動的に次画像へ進む「高速選別モード」を提供する。自動移動の有無は設定可能とする。

### 9.3 選別セッション

以下を対象として、一時的な選別セッションを開始できるようにする。

- 現在のフォルダ
- 選択画像
- 検索結果
- コレクション
- 新規追加画像
- AI生成ジョブ単位の画像群

セッションでは、確認済み件数、採用、除外、保留の件数を表示する。途中終了後の再開および並び順の保存に対応する。

### 9.4 比較表示

初期機能として2枚比較と4枚比較を優先する。

2枚比較:

- 左右それぞれの画像を入れ替え可能
- 一方を基準画像として固定可能
- 同期ズーム、同期パン
- 同期の一時解除
- 左右の入れ替え
- ピクセル等倍表示
- 評価、解像度、容量、形式、キャプション等の比較
- オーバーレイ比較

4枚比較:

- 操作対象の選択
- 選択画像の一時最大化
- 1枚または複数枚の採用
- 残り画像の除外
- 次の4枚への移動
- 基準画像を固定し、他の3枠だけを更新

差分画像の生成や任意枚数比較は将来機能とする。

### 9.5 漫画閲覧

見開きおよび右綴じ表示は初期MVP後の機能とするが、将来機能の中では優先度を高く設定する。

想定機能:

- 単ページ／見開き切り替え
- 右綴じ／左綴じ
- 表紙のみ単ページ
- 奇数ページ位置の調整
- 横長画像の単ページ表示
- 読書位置の保存
- ZIPおよびCBZを一冊として扱う

将来のアーカイブ対応を妨げないよう、データ設計では通常ファイル以外の仮想画像ソースを追加できる余地を残す。

## 10. タグ、キャプション、メモ

以下の情報を別々に保持する。

- 一般タグ: 検索および分類用
- SD学習用タグ列: 順序を持つ学習用データ
- 説明キャプション: 自然言語検索用
- ユーザーメモ: ユーザー管理の自由記述
- AIの元出力および処理履歴

AI生成結果は基本的に自動採用する。ユーザーが編集した項目には手動編集済みの状態を付け、再生成時に自動で上書きしない。

AI処理履歴には、少なくとも以下を保持する。

- 使用したプロバイダーとモデル
- 使用したプロンプトまたはそのバージョン
- 生成日時
- 元の応答
- 採用されたタグとキャプション
- エラー情報

タグの階層、別名、カテゴリ、表記揺れ統合は有用だが、MVPでの対応範囲は未決定とする。

## 11. AIプロバイダー

### 11.1 接続方式

OpenAI互換APIエンドポイントをユーザーが設定できるようにする。初期利用環境として、llama.cpp上で動作するローカルのVision対応モデルを想定する。

接続プロファイルでは以下を設定可能にする。

- 表示名
- Base URL
- APIキー
- モデル名
- Vision対応の有無
- 画像の送信方法
- 最大送信画像サイズ
- タイムアウト
- 同時実行数
- 任意の追加パラメーター
- タグ生成用プロンプト
- キャプション生成用プロンプト

OpenAI互換実装間の差を確認するため、接続、テキスト応答、画像入力、構造化出力を確認できるテスト機能を用意する。

### 11.2 バックグラウンド処理

AI処理はジョブキューとしてバックグラウンドで実行し、UIを停止させない。

ジョブ状態:

- 待機中
- 処理中
- 成功
- 失敗
- キャンセル
- 再試行待ち

キュー全体の一時停止、再開、キャンセル、および失敗ジョブの再試行に対応する。

### 11.3 自動処理

登録ルートごとに以下を設定可能にする。

- 新規画像の自動処理
- タグ生成
- キャプション生成
- 埋め込み生成
- EXIF情報をプロンプトへ含めるか
- GPS情報をプロンプトへ含めるか
- 対象拡張子
- 画像サイズ条件
- 同時実行数
- アイドル時のみ実行
- バッテリー使用中の停止

初回登録時はインデックスとメタデータ抽出を先行する。既存画像すべてをAI処理する場合は、件数を提示してから開始する。登録後に追加された画像は設定に従って自動処理する。

### 11.4 再生成

以下の範囲でAI情報を再生成できるようにする。

- 選択画像
- 現在のフォルダ
- コレクション
- 検索結果
- 登録ルート全体
- 特定モデルまたは古いプロンプトで処理した画像
- 処理に失敗した画像

既存結果は新しい処理が成功するまで保持し、手動編集済み情報を保護する。

## 12. メタデータ

### 12.1 基本方針

EXIF、IPTC、PNGメタデータは読み取り専用とし、元画像へ書き戻さない。

読み取った情報は以下の2層で管理する。

1. 元ファイルに格納された生データ
2. 表示、検索、絞り込みに利用する正規化データ

### 12.2 写真メタデータ

EXIF等から取得した以下の情報を情報ビューと検索に利用する。

- 撮影日時
- GPS位置
- カメラおよびレンズ
- 露出等の撮影条件
- 画像方向
- その他の利用可能な項目

GPS情報を外部またはローカルLLMへ送信するかは、通常のEXIF情報とは別に設定可能とする。

### 12.3 PNG生成メタデータ

既知形式は解析して共通項目へ正規化する。

初期対応候補:

- Stable Diffusion WebUI／Forgeのparameters
- ComfyUIのpromptおよびworkflow
- NovelAI系メタデータ
- InvokeAI等の識別可能な形式
- 一般的なPNGテキストチャンク

未知形式も破棄せず、Raw metadataとして表示およびコピーできるようにする。

情報ビューでは以下を可能な範囲で表示する。

- Positive prompt
- Negative prompt
- Model
- VAE
- Sampler
- Scheduler
- Steps
- CFG scale
- Seed
- 生成サイズ
- Clip skip
- LoRA
- ControlNet
- 使用ツール
- ComfyUI workflow
- Raw metadata

長文プロンプトやワークフローは折りたたみ表示し、各項目をコピーできるようにする。ComfyUI workflowはJSONとしてコピーまたは書き出し可能にする。

PNG内のメタデータをDBへキャッシュし、ファイルが変更された場合だけ再解析する。DBからPNGへは書き戻さない。

### 12.4 重複判定上の区別

メタデータだけが異なる画像を扱えるよう、将来的に以下を区別する。

- ファイル完全一致: ファイルのバイト列ハッシュ
- ピクセル一致: デコード後の画素に基づくハッシュ
- 視覚的類似: 画像埋め込みによる類似度

MVPで実装する判定方式の範囲は未決定とする。

## 13. 検索

### 13.1 基本方針

1つの検索UIから、以下を組み合わせて検索できるようにする。

- キーワード検索
- タグ検索
- ファイル名およびパス検索
- EXIF等の条件検索
- 評価、選別状態、お気に入りによる絞り込み
- キャプション等に対する自然言語の意味検索

高度な検索構文に加え、タグ、評価、期間等をGUIから指定できるようにする。

検索構文の例:

```text
青い髪の少女 tag:night rating:>=3 type:png
model:"model-name" steps:>=30 has:workflow
```

### 13.2 意味検索

検索対象の文章は、原則として以下から構成する。

- AIキャプション
- 検索用タグ
- PNGのPositive prompt
- ユーザーメモ
- 検索利用が適切なEXIF由来情報

Negative promptは画像に存在しない要素を含むため、意味検索用文章へは混ぜず、明示検索の対象とする。ComfyUI workflow全体も意味検索用文章へは混ぜない。

日本語テキスト埋め込みモデルとしてruri-v3を採用する。

MVPではruri-v3-70mを標準、ruri-v3-30mを軽量選択肢とする。設定から自然言語検索を有効化した際に、検証済みのONNXモデルをHugging Faceから取得し、独立したRustワーカープロセス上のONNX RuntimeでCPU実行する。詳細は[埋め込みモデル実行・配布方針](./embedding-runtime.md)に定義する。

埋め込みベクトルはSQLiteを正本とし、通常検索には再生成可能なUSearch HNSWインデックスを使用する。USearchを利用できない場合はRustによる正確検索へフォールバックする。FAISSおよび独立したベクトルDBはMVPでは採用しない。

検索結果は、ベクトル類似度だけでなくタグ、ファイル名、パス等の一致を統合したハイブリッドランキングとする。可能な範囲で、キャプション類似、タグ一致、EXIF一致などの検索根拠を表示する。

### 13.3 RAG

MVPでは自然言語による画像検索を優先する。検索結果のメタデータをLLMへ渡し、画像群に対する質問へ回答させる本来のRAG機能は将来機能とする。

### 13.4 画像類似検索

キャプションの意味検索と、画像の見た目に基づく類似検索は別機能として扱う。CLIP系モデル等を使う画像類似検索は将来機能とする。

## 14. バックアップと復元

通常運用では中央SQLiteデータベースを正本とする案を基本とする。画像本体はDBへ格納しない。

詳細なエンティティ関係、検索インデックスおよびキャッシュの扱いは、[データモデル草案](./data-model.md)に定義する。

想定するアプリデータ:

```text
app-data/
├── library.sqlite
├── thumbnails/
├── embeddings/
└── logs/
```

登録ルートごとに、移行および障害復旧用のポータブルバックアップを任意に作成できるようにする。

想定例:

```text
registered-root/
└── .gento/
    ├── metadata.jsonl
    ├── collections.json
    └── backup-info.json
```

メタデータバックアップには、相対パス、内容ハッシュ、タグ、評価、お気に入り、選別状態、キャプション、メモ、AI処理履歴等を含める。

バックアップ形式、`.gento`という名称、自動バックアップの頻度、埋め込みをバックアップへ含めるかは未決定とする。

## 15. Stable Diffusion学習用エクスポート

選択画像、フォルダ、検索結果、コレクションを対象に、学習用データセットとして書き出せるようにする。

初期想定:

- 画像のコピーまたは変換
- 画像と同名の`.txt`キャプション
- SD学習用タグ列の順序を維持
- 出力先でのファイル名衝突を解決
- 必要に応じたフォルダ構造の維持または平坦化

画像のリサイズ、形式変換、タグ加工ルール等の詳細は未決定とする。

## 16. プライバシーと認証情報

- 自動AI処理はユーザーが有効化した登録ルートだけで実行する
- 接続先がローカルか外部かを分かりやすく表示する
- EXIF送信とGPS送信を個別に制御する
- 送信前に画像を縮小する設定を提供する
- APIキーは可能な限りOSの資格情報ストアへ保存する
- プロンプト、応答、エラーログの保存範囲を設定可能にする

## 17. 性能要件

主な対象規模は数万枚とする。一般的なローカルSSD上の画像を想定し、以下を目標とする。

- 起動後、インデックス処理の完了を待たずにUIを操作できる
- フォルダ移動後、先頭のサムネイルを速やかに表示する
- キャッシュ済み画像の前後移動で目立つちらつきを生じさせない
- 一覧には仮想スクロールを使用し、全画像のUI要素を同時生成しない
- 現在位置および移動方向に応じて画像を先読みする
- サムネイル生成、メタデータ抽出、AI処理の優先度を分離する
- AI処理中も閲覧、検索、ファイル操作を阻害しない
- 低解像度プレビューを先に表示し、高解像度デコードを段階的に反映できる

具体的な起動時間、表示時間、メモリ上限等は、技術検証後に数値化する。

## 18. 技術構成

技術スパイクの自動計測とLinux開発機での手動確認を通過したため、Tauri 2、Svelte 5、TypeScriptおよびRustをMVPの技術基盤として採用する。

- デスクトップシェル: Tauri 2
- フロントエンド: Svelte 5、TypeScript
- アプリケーションコア: Rust
- 永続化: SQLite

大量画像表示の初期技術スパイクはLinux開発機上でPASSとなった。低スペック環境、実5万ファイル、巨大画像、WindowsおよびmacOSはMVP中の追加検証ゲートとする。

初期試作はLinux開発機と`sample/dataset`を使用した。詳細な計画と結果は[高速画像表示 技術検証計画](./technical-spike.md)および[技術スパイク報告](./technical-spike-report.md)に記録する。MVPの実装順序と受け入れ条件は[MVP実装計画書](./mvp-implementation-plan.md)に定義する。

### 18.1 アーキテクチャ原則

再利用性とUI方式の交換可能性を維持するため、RustコアはTauriから独立させる。ドメインモデル、ファイル操作、画像処理、DB、検索、AI処理ではTauri固有型を使用しない。

想定するRust workspace:

```text
crates/
├── gento-core       # ドメインモデルとユースケース
├── gento-db         # SQLite
├── gento-image      # デコード、サムネイル、メタデータ
├── gento-search     # 全文検索とベクトル検索
├── gento-ai         # OpenAI互換APIとジョブ
├── gento-platform   # OS別ファイル操作
└── gento-tauri      # Tauriアダプター

apps/
└── desktop          # Svelte 5／TypeScript UI
```

UI側には全ライブラリを保持せず、表示範囲とその周辺に必要なデータだけを渡す。検索、ソート、DB、画像デコード、サムネイル生成、AIジョブ等はRust側で行う。

RustとWebView間のIPCでは、画像バイト列や巨大な配列をJSONとして受け渡さない。IPCはID、状態、命令、ページ単位の検索結果等に限定し、画像とサムネイルはアクセス範囲を制限したローカルプロトコル経由で提供する。

WebView固有の画像形式対応へ依存せず、サムネイル、特殊形式、巨大画像等はRust側で一貫した表示用データへ変換する。

### 18.2 フロントエンド方針

Svelte 5の細粒度なリアクティブ更新を利用し、選択、評価、選別状態、ジョブ進捗等の更新範囲を局所化する。サムネイル一覧には仮想化を用い、必要に応じてTanStack Virtualまたはそのコアを利用する。

アプリケーションの正本となる状態はRust側へ置き、UI側には選択ID、表示中ページ、スクロール位置、ペイン状態、一時編集中の値等を保持する。

## 21. 用語

- 登録ルート: タグ、AI処理、検索等の拡張機能を有効にした最上位ディレクトリ
- 画像内容: ファイルパスとは独立して扱う、画像データとその論理的メタデータ
- ファイル実体: ファイルシステム上に存在する個別のファイル
- コレクション: ファイルを移動せず画像をまとめる仮想分類
- スマートコレクション: 保存された検索条件に一致する画像を動的に表示するコレクション
- 選別状態: 未選別、採用、除外のいずれかを表す属性
- 意味検索: テキスト埋め込みを使い、自然言語の意味的な近さから画像を探す機能
- RAG: 検索結果をLLMへ渡し、その情報を根拠として回答を生成する機能
