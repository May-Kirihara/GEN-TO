## 成果物の概要

設計正本 docs/embedding-runtime.md §6-7/§10 とWP指示の設計方針に従い
実装。**依存方向の設計判断**: USearchラッパは gento-embedding の新module
`vector_index` (モデルidentityがmanifest由来のため。crateは引き続き
DB非依存)、RRF融合は gento-search の新module `hybrid` (純Rust・usearch
非依存で決定性テスト容易)、SQLite読み出しと編成は gento-tauri
(両crateへ依存済みの thin adapter)。既存の core←search/db 方向に違反なし。

### 1. USearch索引ラッパ (`crates/gento-embedding/src/vector_index.rs`)

- `usearch` =2.26.2 (Apache-2.0。**dependency-notes先行記録済み** —
  cxx-buildによるC++17その場コンパイル+numkong静的リンク。ビルド時に
  C++17コンパイラ要求。`cxx` =1.0.199はlock既存の直依存化)。
- 索引単位 = モデルidentity (name+revision+dims)。保存先
  `{data_dir}/indexes/{model-id}/` に `index.usearch` + `identity.json`
  sidecar。**sidecarと索引ヘッダの二重identity検証**でモデル/revision/
  次元の混在を構造禁止 (§10)。
- metric=Cos (L2正規化済み前提。similarity = 1-distance)・F32。
  パラメータ: connectivity=16 / expansion_add=96 /
  **expansion_search=64** (24だと5万計測でrecall@10 0.92 → 64で0.995)。
- tmp書き込み→renameのアトミック保存。ラッパ層で容量自動倍加
  (usearchはreserve先行必須のため増分追加を吸収)。

### 2. RRF融合 (`crates/gento-search/src/hybrid.rs` — 純Rust)

- **数式 (api-contract §46固定)**:
  `score(d) = w·1/(60+rank_sem(d)) + (1-w)·1/(60+rank_kw(d))`
  (k=60固定・w∈[0,1]・不在項=0・同点はasset id昇順で決定的)。
- 単体テスト: 数学的厳密性・w=0/1境界・重みによる順位逆転・clamp・
  重複入力防御。

### 3. 索引管理サービス (`apps/desktop/src-tauri/src/vectorindex.rs`)

- `VectorIndexService`: 起動・有効化時に再読込 (acceptance)。件数不整合
  なら旧索引で検索させつつバックグラウンド全再構築→完了後切替 (§10)。
  破損時はファイル破棄→SQLiteから再構築 (進捗イベント)。
- 増分: 埋め込みジョブ完了フック (`EmbeddingService.set_vector_sink`) で
  稼働索引へ即追加。30秒定期保存 + graceful shutdown時flush。
  crash時は次回起動の件数照合→再構築が拾う (派生データ設計)。
- モデル切替・削除: identity照合で旧索引自動無効化 / ファイル破棄。
- Commands: `vector_index_status` / `vector_index_rebuild`。
  Events: `vector-index:progress|ready|notice` (JSON文字列payload)。

### 4. ハイブリッド検索パイプライン (`apps/desktop/src-tauri/src/search.rs`)

- `search_run` に `semanticWeight` (0..1・clamp) 追加。**w=0は旧経路の
  まま (完全互換)**。w>0: 意味側 (worker `embed_query` レイジーロード
  45s上限 → USearch top-200・構造フィルタは事前SQL集合で
  `filtered_search`) × キーワード側 (MATCH語あり: **bm25順** top-200
  `keyword_ranked_asset_ids` / なし: id昇順) を重み付きRRF融合。
  結果は融合上位 (最大400件) を表示。`semanticScores` (assetId→cosine)
  を応答に含め、InfoPanelが「意味 xx%」表示。
- フォールバック: 埋め込み無効・索引未構築・ロード失敗時は警告付きで
  キーワード検索へ (§8: キーワード検索は常時機能)。
- `similar_search_run(assetId, k?)`: 対象assetのdocベクトル近傍
  (自己除外・類似度順・k既定50)。`search_refresh` は類似画像表示は
  同assetで再検索、ハイブリッド表示は保存済み重みで再実行
  (SearchDisplayにkindと重みを保持)。
- `SearchRunDto` に `kind`・`semanticScores` 追加 (camelCase・形状テスト)。

### 5. UI統合

- 検索バー: 重みスライダー「キーワード⇔意味」 (0..100%・5%刻み。
  埋め込み無効・索引未構築時はdisabled+理由title)。
- グリッドコンテキストメニュー + InfoPanelに「類似画像を検索」
  (無効時は理由tooltip。ContextMenuのMenuActionにtitle追加)。
- InfoPanel: 意味スコア表示 (検索時「意味 xx%」/類似時「類似度 xx%」)。
  検索一致 (キーワード根拠) 表示はそのまま併存。
- ヘッダー: 索引構築進捗 `索引構築中 x / y`。
  AIパネル自然言語検索タブ: 索引状態行 ( 構築中/準備完了/準備中/未構築)。
- `lib/search.ts` (runSimilar・semantic写像・semanticPercent/weightLabel)
  + `lib/vector-index.ts` (新規) + テスト。

## 実装中に発見・修正した重要事項

1. **usearchのreserveは自動拡張しない**: 「Reserve capacity ahead of
   insertions!」エラー。ラッパ層で容量倍加を吸収 (増分追加の用途上必須)。
   また容量0の索引への検索もErrになるため空索引は空結果を返す。
2. **expansion_search=24はrecall不足** (5万計測0.92): 64で0.995。
   検索レイテンシはほぼ不変 (0.35ms)。
3. **`Db.with_writer` は非再入**: テストのseedingでwriter内でwriterを
   呼ぶデッドロックを一度出した (修正済み — seedingは外で実施)。
4. **`GENTO_EMBEDDING_MODELS_DIR` 相対指定の解決バグ (WP-11潜在)**:
   `embedding_service.rs` のテストはmanifest dirから2親上が`apps/`に
   なり、`.local-models`相対指定だと**環境ゲート済みテストが無音スキップ**
   していた (WP-11の文書化コマンドは実際にはスキップ状態だった)。
   3親上へ修正済み — 修正後にWP-11 E2Eが初めて実実行されPASSを確認。
5. `bm25()` はFTSテーブルをFROMに直接置くJOIN形でも機能する
   (`keyword_ranked_asset_ids` の実装)。構造フィルタは前置述語
   (`filtered_search`) 採用 — 取得後フィルタより5万規模で高速 (0.55ms)。
