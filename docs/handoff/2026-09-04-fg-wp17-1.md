## B1. 起動掃除の所有権・削除モデル (最重要・レビューblocker)

### 設計 (record拡張の実装場所・旧record扱い)

- **不変条件**: 削除は「op recordによるpath所有権」かつ「fd同一性検証
  (`(dev, ino)`)」の**両方**を満たす場合のみ。厳密tmp文法への名前一致
  (uuid検証含む) **だけでは削除しない** — 文法は `.gento-tmp-` 類似
  ファイルの**報告フィルタ**としてのみ使用 (旧 `owned.contains(path) ||
  is_owned_tmp_name(name)` の `||` を実質 `&&` へ再構築)。
- **record拡張の実装場所**: `StepResult.tmp_file_id: Option<OsFileId>`
  (`#[serde(default)]`) — **`file_operations.result_json` 内のJSON拡張**
  でありDBスキーマ変更 (migration) 不要。`OsFileId` にserde deriveを追加
  (JSON表現 `{"dev":..,"ino":..}`)。
- **IDの捕獲点**: `FileOpsFs::copy_file` に出力引数 `tmp_file_id` を追加。
  実装は**排他create_new直後の作成fdに対するfstat**から `(dev, ino)` を
  設定する (成功・失敗の両経路で — 失敗残留こそ掃除対象。pathnameの
  再statは差し替え競合を含むため不使用)。`move_file` (跨界フォール
  バックのcopy) は同じ出力引数を透過。
- **旧recordの扱い (fail-closed)**: `tmp_file_id` を記録しない世代の
  record (= 本変更前のresult JSON・executing残留のrequest再構築分・
  OSファイルIDを取得できない環境=Windows) は**削除せず残留報告**
  する。設計判断: 旧recordのtmpは自己識別的dotfile (`.{名前}.gento-tmp-
  {uuid}-{seq}`) かつ走査 (`is_image_entry`) 対象外のため残留は無害。
  DBマイグレーション禁止のため、後付けのID補完は不可能 — fail-closed
  が唯一安全 (WP委任仕様どおり)。
- **traversalと削除**: `gento-core path_safety::OutputDir` (既存のfd
  ピン留め機構) を使用。登録ルートを `O_DIRECTORY|O_NOFOLLOW` で開き、
  サブディレクトリも `openat(O_NOFOLLOW|O_DIRECTORY)` (`open_existing_
  subdir`) で開き直すfd歩行 — **dir→symlink差し替えで登録ルート外に
  出ない**。削除対象は `O_NOFOLLOW` で開いたfd (`open_regular_at`) が
  通常ファイルであることをfstat確認した後のみ、親fd相対の `unlinkat`
  (`remove_file_at`) で削除。
- **列挙機構の追加**: `OutputDir::entries()` (unix: `fdopendir`+`readdir`
  — errno区別は `clear_errno` (linux `__errno_location` / darwin
  `__error` のcfg分岐)、d_type不明は `fstatat(AT_SYMLINK_NOFOLLOW)` で
  補完。非unix: `read_dir`)。`dup` がopen file descriptionを共有する
  問題は `rewinddir` で対処 (再列挙可)。
- **正直に文書化した残存窓・限界** (api-contract §41):
  - fstat確認→unlinkat間のナノ秒オーダー窓は構造的に除去不可
    (Linuxにfd基準の削除APIが存在しないため)。
  - プロセス死亡でstep結果がresult JSONへ確定する前のtmp (executing
    残留のrequest再構築分) はino記録が存在しないため**fail-closed残留
    報告** (自動削除されない — 毎起動ログ通知。手動削除または将来の
    段階的設計課題)。
  - undo経由のtmp (跨界undoフォールバック・`UNDO_TMP_SEQ_BASE`帯) は
    recordへpath/IDを登録しないため同様にfail-closed報告。
  - Windows: `os_file_id_of` が常時 `None` のため全recordがID無し →
    掃除は**削除を行わず残留報告のみ** (fail-closed。platform-notes §2)。
- **fakeの規約同一化**: gento-core テストの `FakeFileFs.copy_file` が
  AlreadyExists経路でtmpをunlinkしていた (RealFileOpsのnever-unlinkと
  不一致) → unlinkを廃止しnever-unlink規約へ同一化。ID報告も実装。

## B2. is_lexically_beneath の trailing whitespace bypass (レビューblocker)

- **修正**: `input.trim()` を廃止 (verbatim根系のtrailing spaceを破壊
  していた)。形式ごとの正確な意味論を実装:
  - verbatim (`\\?\` / `\\?\UNC\`): 区切りは `\` のみ (`/` はNT名前空間
    では名前の一部 — 過大一致防止)。成分末尾のspace/dotは**保存**。
    `.`/`..` 成分は解釈不能のため**拒否** (fail-closed)。
  - 非verbatim (Win32): 区切り `\`/`/` 両方。成分末尾のspace/dotは
    Win32実解決相当に剥す。`.`除去・`..`字句解決 (clamp維持)。
  - **両辺の正規化形式が不一致 (verbatim vs 非verbatim) なら字句一致を
    信用せず拒否** (fail-closed。実運用の呼び出しは両辺canonicalize出力
    = verbatim同士のため影響なし — Windows実機のcanonicalize検証に委ね
    る設計であることをdoc明記)。
  - malformed UNC (server+shareの2成分未満) は錨にも経路にもならない。
  - 大小同一視は**ASCIIのみ** (Unicodeケース相違は不一致=拒否側 —
    B4の過大表現修正を兼ねる)。
- **red→green**: 新規7テストが旧実装でFAILED (レビューのbypass本体
  `\\?\C:\safe ` 根への `\\?\C:\safe\evil` を含む) → 新実装で全緑。
  既存のmix形式相互運用テスト (verbatim/非verbatim混在でtrue表明) は
  新fail-closed規約の側へ更新。
- **追加テスト**: verbatim根のtrailing space/dot (保存・bypass拒否)・
  非verbatimのWin32剥離・`/`混在separator・verbatim UNC+`/` (非区切り)・
  root clamping組合せ+verbatim `..` 拒否・malformed UNC・Unicodeケース
  (ASCII-only folding限界のfail-closed検証)・`//` UNC拒否・ドライブ相対
  (`C:x`) 拒否・先頭空白拒否。

## B3. redaction の終端space成分漏れ (non-blocking → 修正)

- **修正** (`redact.rs` `path_candidate_end`): 空白継続に後続separatorが
  無い場合も、空白トークン単位で (i) ドットを含むトークン (拡張子らしい
  ファイル名断片) または (ii) 経路側が非ASCIIを含む場合の非ASCIIトークン
  (ドット無し日本語ファイル名) までパス候補を延長する。**最後の該当
  トークンで打ち切る**ため後続通常語 (`ignored`) とASCII-only経路+日本語
  通常文 (`/tmp/x.png 保存しました`) は従来どおり保持。
- **red→green**: 新規3テストが旧実装でFAILED (`/home/山田/マイ 写真.png`
  の `写真.png` 漏れ本体を含む) → 全緑。既存ポリシーテストは全て無傷。
- api-contract §49 に終端spaced成分の規約と残る限界 (ドット無非ASCII・
  経路ASCII限定の拡張子なしspaced名は検出不能) を明記。

## B4. 整合修正

- **dir_free_bytes / free_bytes コメント整合** (fail-open/error):
  実装は `None`→`Err` 変換だが、唯一の呼び出し経路 (gento-core
  `plan_file_op` の `disk_shortfall_bytes` 計算) が `Err` を `.ok()` で
  打ち切るため**実質fail-open (確認skip)**。この正確な連鎖を両サイトの
  コメントへ明文化 (「確認skip — fail-open」の曖昧記述を修正)。
- **Windows case folding の過大表現**: path_safetyのdoc・api-contract
  §47対応表を「ASCIIのみの大小同一視 (Unicodeケース相違は不一致=拒否側
  に倒す)」へ修正+検証テスト追加。
- **Windows installer targets**: `tauri.conf.json` の `bundle.targets`
  に `nsis`, `msi` を追加。`icons/icon.ico` (既存128x128 PNGのICO
  ラップ) を追加。`webviewInstallMode` は明示設定せずTauri v2既定
  (`downloadBootstrapper`) を使用 (platform-notes §8.1に記録)。
  ※Linuxホストではbundle生成検証不可 — Windows実機フェーズでの確認が
  必要 (レビュー指摘の「installer build」は未実施のまま)。
