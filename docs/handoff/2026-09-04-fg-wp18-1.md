## F1. notices生成の恒久policy化と5件追加 (blocker)

### レビュー指摘

`anstyle 1.0.14` / `clap 4.6.6` / `clap_builder 4.6.6` / `clap_lex 1.1.0` /
`cxxbridge-cmd 1.0.199` はCargo.lockに存在するのにlicenses.mdに掲載が無い。
旧generatorは `cargo metadata` の解決graph (`resolve.nodes`) を抽出基盤に
しており、単なる再実行では直らない。

### 原因の実証

`cxx` がoptional依存として `cxxbridge-cmd` を持ち (→ clap → clap_builder →
anstyle/clap_lex)、feature defaultでは解決graphに入らない。
`cargo metadata` (default / `--all-features` いずれも) の `packages` に
5件とも**存在しない**ことを実測確認。Cargo.lock (691 package = workspace
8 + 外部683) とmetadata外部package (678) の差分は**この5件のみ**だった
(残り678件は完全一致 — metadata ⊂ lockfile)。

### 恒久policy (決定・文書化済み)

> **配布scope = Cargo.lockの全 `[[package]]`** (workspaceメンバー +
> build-tool系を含む)。cargo metadataの解決graphはfeature/target構成で
> 変動しoptional依存が零れ得るため正本としない。license・入手元の情報源は
> cargo metadata とし、metadataに現れないlockfile限定packageは
> generator内の補完表 (crates.io確認済み) から取る。Cargo.lockに存在して
> metadataにも補完表にも無いpackageがある場合は**エラーで生成を中止**する
> (無掲載の放置を構造的に防ぐ)。完全性は `licenses_notice` unit test
> (gento-tauri) が `cargo test --workspace` で常時検証する。

文書化箇所: `scripts/gen-licenses.sh` ヘッダコメント (policy本文) /
生成物 `docs/dev/licenses.md` ヘッダ (配布物から見える説明) /
`docs/dev/release-checklist.md` §3.5 (RCゲート手順) / 本handoff。

補完表の5件はcrates.io APIで本WP中に再確認 (licenseは全て
MIT OR Apache-2.0 — WP-18-2ハンドオフの調査と一致):

| package | license | repository |
|---|---|---|
| anstyle 1.0.14 | MIT OR Apache-2.0 | https://github.com/rust-cli/anstyle |
| clap 4.6.6 | MIT OR Apache-2.0 | https://github.com/clap-rs/clap |
| clap_builder 4.6.6 | MIT OR Apache-2.0 | https://github.com/clap-rs/clap |
| clap_lex 1.1.0 | MIT OR Apache-2.0 | https://github.com/clap-rs/clap |
| cxxbridge-cmd 1.0.199 | MIT OR Apache-2.0 | https://github.com/dtolnay/cxx |

### 実装

- **`scripts/gen-licenses.sh`**: Rust抽出をlockfile走査 (awkで全
  `[[package]]` を name/version/source抽出。引用符付き行のみmatchさせる
  ことでlockfile先頭 `version = 3` ヘッダを除外) に変更。license/repository
  は metadata (bash連想配列 `name version` キー) → 補完表の順で解決し、
  両方missなら補完表追記を促すエラーを出して**生成ファイルを残さず中止**。
  source行なし = workspaceメンバーは従来どおり `(workspace)` 表示。
- **回帰テスト** `apps/desktop/src-tauri/src/licenses_notice.rs` (新規、
  lib.rsに `#[cfg(test)] mod licenses_notice;` 登録 — 本体コード無し):
  1. `every_cargo_lock_package_is_listed_in_third_party_notices` —
     Cargo.lock全package (name, version) がlicenses.mdの**Rust表**の行
     `| name | version |` として存在することを全数検証 (lockfileと同じ
     parser概念をRustで再実装 — 依存追加なし)
  2. `notices_list_build_tool_packages_outside_cargo_metadata_graph` —
     上記5名 (版ではなく名前で固定: 版bumpで陳腐化しない) の掲載を検証。
     generatorがmetadata基準に後退したら即座に赤になる
- licenses.mdのnoticesはこのtestで常時ロックされるため、依存変更後に
  再生成を怠ると`cargo test --workspace`が赤になる (checklist §3.5に明記)。

事前確認 — 計測汚染防止規約)。3形式すべてで
`licenses/THIRD-PARTY-NOTICES.md` に5件が入っていることを**実物展開で**
検証した:

| 形式 | 展開手法 | 検証結果 |
|---|---|---|
| deb | `dpkg-deb -c` + `dpkg-deb -x` 展開 | `usr/lib/GEN-TO Spike/licenses/THIRD-PARTY-NOTICES.md` に5件すべて (25/88/89/90/123行目) |
| rpm | 純Python header解析 (`/tmp/opencode/wp18_rpm_extract.py`: lead 96B + signature header (8B整列) + header をスキップしpayload (gzip圧縮cpio) のoffset=2929を算出) → `gzip -d \| cpio -i --to-stdout` | `./usr/lib/GEN-TO Spike/licenses/THIRD-PARTY-NOTICES.md` に5件すべて |
| AppImage | `--appimage-extract` | `squashfs-root/usr/lib/GEN-TO Spike/licenses/THIRD-PARTY-NOTICES.md` に5件すべて |
