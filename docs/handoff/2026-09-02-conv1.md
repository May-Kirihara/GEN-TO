## WP-11への引き継ぎ事項

1. **グラフ契約**: 入力 `input_ids`/`attention_mask`（動的軸 batch/sequence・
   int64）、出力 `last_hidden_state` のみ。**pooling/L2正規化はグラフ外**——
   worker側で attention mask考慮mean pooling + L2正規化を実装すること。
   実装済み参考: `scripts/verify-ruri3-onnx.py` の `encode_candidate`。
2. **tokenizer**: `tokenizer.json` を `tokenizers` crate で直読みする想定で検証済み
   （transformers AutoTokenizer と全32文でid完全一致）。truncationは
   `enable_truncation(8192)`（特殊トークン込み8192に切り詰め。手動スライスは
   BOS/EOS位置がズレるので不可）。70m/30mでtokenizer.jsonは同一ファイル。
3. **manifest**: `docs/dev/ruri3-onnx-manifest.json` が正本。接頭辞
   （検索クエリ: /検索文書: ）・次元・max 8192・cosine・mean_tokens・l2を含む。
   onnxruntimeは1.29.0で検証。「必要最低版」はort crate版の採用時に確定すること。
4. **訂正**: handoff 2026-09-02-mvp-wp11.md の safetensors etag 欄は
   Xet CASハッシュ（sha256ではない）。正しいsha256は
   70m `c959b76a…` / 30m `e94155e3…`（tree API lfs.oid で確認、本manifestに記録）。
