## 変更内容 (意図ベース)

1. **`crates/gento-db` 新設** — SQLite基盤 (メタデータの正本):

     単一writer接続を `Db::with_writer` がMutexで直列化。読み取りは
     `Db::with_reader` が分離接続 (WALなのでwriterをブロックしない。
     idle 2本保持、貸出集中時のみ追加接続を開き返却時に閉じる)。

## 逸脱・判断記録

- **DB open失敗時もアプリ続行**: setup失敗で落とす代わりに
  `AppState.db=None` + warnログ。理由: 本WP時点でDBを必要とする製品機能
  は未実装 (WP-2以降) であり、DB不調でファイラーとしての起動まで妨げる
  リスクを避けた。WP-2で登録ルート機能が入る際にこの方針を再検討すること
  (DBなしでは登録機能が使えない旨のUI案内が必要になる)
- **`synchronous=NORMAL` 採用**: PM指示には未指定のため判断記録。
  WAL+NORMALはSQLite公式推奨 (アプリクラッシュで破損なし、電源断で
  直近トランザクション喪失の可能性)。画像カタログ用途に適合
- **backupの実装は `VACUUM INTO`**: 指示は「Backup API または VACUUM INTO」
  のいずれか。rusqliteのbackup featureは接続間copyの正規手段として有効化
  したが、実装はファイルへ書き出すVACUUM INTOを採用 (コードが単純・
  接続を跨がない・WAL未checkpoint分を含むことをテストで証明)
- **`crash_simulation` の `std::mem::forget`**: 接続を閉じずにリーク
  させることでプロセス死亡をシミュレート (テストプロセス内で1回のみ。
  実害なし)
- **reader接続はREAD_WRITEで開く**: 読み取り専用フラグにするとWAL
  recovery場面 (クラッシュ直後等) で書き込みが必要になり失敗し得るため
  — **改訂 (FG-WP1) で置き換え**: 接続フラグはREAD_WRITEのまま
  `PRAGMA query_only=ON` を設定しSQL文レベルで書き込みを拒否
  (WALのpager処理は妨げない。冒頭改訂節2参照)
- **`hash_algorithm` CHECKは'blake3'のみ**: 将来アルゴリズム追加時は
  migrationで拡張 (追加方式方針に従う)
- api-contractの`db_status`は§16として追記 (§14 devtoolsの後に連番)
