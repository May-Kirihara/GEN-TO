## G. Linux配布物の成立

### G-1. bundle生成 (3形式)

`tauri.conf.json` の `bundle.targets` を `["deb"]` →
`["deb", "rpm", "appimage"]` へ更新し `pnpm --dir apps/desktop tauri build`
を実行。**AppImageも成功** (ネットワーク経由でlinuxdeploy/AppRun/
plugin群をDL — 初回のみ`~/.cache/tauri`へキャッシュ。失敗時の
deb/rpm代替条項は不使用)。

| 形式 | path | サイズ | sha256 |
|------|------|--------|--------|
| deb | `target/release/bundle/deb/GEN-TO Spike_0.1.0_amd64.deb` | 23,644,050 B | `e7584eff5fbf8c4bb43895fc529f1d46ed92641721c3021d21e6a56703fc9f93` |
| rpm | `target/release/bundle/rpm/GEN-TO Spike-0.1.0-1.x86_64.rpm` | 23,645,067 B | `ca4b2e77a246218f08add89ff6c9d18552aa9dbb1e18a6252f5ed52aa64f13d4` |
| AppImage | `target/release/bundle/appimage/GEN-TO Spike_0.1.0_amd64.AppImage` | 97,999,352 B | `6904b1ed92ff9f1135d29fca48d7a8ac22e7d204f17490f0f59c95b263104de8` |

- **deb**: `dpkg-deb -I/-c`で検証 — `Depends: libwebkit2gtk-4.1-0,
  libgtk-3-0`。`/usr/bin/gento-tauri` (68MB) + .desktop + hicolor
  アイコン。システムWebKitGTKに動的リンク。
- **rpm**: 環境にrpmコマンドが無いため**純PythonでRPMヘッダを解析**
  (`/tmp/opencode/wp17_rpm_inspect.py` — リード96B+署名/本体ヘッダ
  index読み) — `Requires: libwebkit2gtk-4.1.so.0()(64bit),
  libgtk-3.so.0()(64bit)`・ファイル一覧はdebと同一構成。
- **AppImage**: linuxdeploy GTK pluginで**GTK3/WebKitGTK一式を同梱**
  (約98MB = debの4倍)。FUSE不在環境は`--appimage-extract-and-run`。

**動作方式**: フロントエンド資産はバイナリ埋め込み (tauri
custom-protocol・`resources`/`externalBin`定義なし)。埋め込みモデル
(ruri3 ONNX) は配布物外 — 実行時に`--models-dir`/`GENTO_MODELS_DIR`/
既定dirへDL (gento-embedding)。DB/キャッシュもユーザー領域。

## H. 政策決定の実装 (§24申し送りの決着)

### H-1. 100MP 256MiB保護上限 — 上限維持 + メッセージ改善

- **挙動確認**: 既存テスト2件 (寸法bomb PNG・JPEG 65500²) +
  baselines §4実測 (102MP PNG → 0.3ms拒否・UI継続) で、超過時は
  `ImageError::Limits` → `thumb:failed`イベント → 失敗セル記録
  (再要求なし) が確定。100MP表示はoriginal (`gento-original:`) 経由で可。
- **改善 (red→green)**:
  - Rust: `ThumbnailError::Decode`のDisplayが`ImageError::Limits`を
    特別扱いし「`画像が大きすぎるため上限で拒否しました (上限:
    デコード割り当て256MiB・1辺20000px)` + 元エラー」を返すよう変更
    (`crates/gento-image/src/thumbnail.rs`)。新規テスト
    `limits_error_message_tells_the_user_the_reason_and_the_limits`が
    旧実装で失敗 (red: `decode failed: Image size exceeds limit`に
    上限値も理由も無い) → 実装後緑。
  - UI: `FailureSet`が失敗理由を保持 (`record`/`reasonFor`・
    retract/clearで連動消去) し、`GridStore.failureReasonFor`経由で
    失敗セル (✕) のtooltipに理由を表示
    (`ThumbnailGrid.svelte` `failReasonTitle`)。vitest 2件
    (demand.test.ts・grid-store.test.ts) がred→green。
- **政策記録**: platform-notes §7.1 + baselines §12.4。

### H-5. ごみ箱・外部アプリ起動のOS別挙動

実装確認の上、platform-notes §7.5に表で記録:

- ゴミ箱 (trash crate 5.2.6): Linux=XDG Trash仕様+trashinfo特定
  (検証済み) / Windows=`IFileOperation`でRecycle Bin (undo特定は
  未検証・macOSと同じ課題) / macOS=`NSFileManager.trashItemAtURL`
  (trashinfo不在でundo特定失敗 → §3.3既知制限)。

  既定アプリ = xdg-open / ShellExecuteW / `/usr/bin/open`。
  ファイルマネージャー表示 = DBus FileManager1.ShowItems (portal fallback) /
  SHOpenFolderAndSelectItems / NSWorkspace.activateFileViewerSelectingURLs。
