# MVP-WP-0 引き継ぎ: スパイクから製品基盤への移行 (2026-08-30)

## 変更内容 (意図ベース)

1. **devtools feature隔離 (最重要)**: 計測・検証専用機能をcargo feature
   `devtools` (既定無効) でコンパイル隔離した。ゲートは
   `#[cfg(any(debug_assertions, feature = "devtools"))]` で、debug buildでは
   従来どおり常時含まれ、通常releaseビルドには環境変数 (`GENTO_DEV_BRIDGE`)
   に関係なく存在しない。計測用release buildは
   `cargo build --release -p gento-tauri --features custom-protocol,devtools`
   (tauri CLI経由は `pnpm tauri build --no-bundle -- --features devtools`。
   **cargo直接ビルドでは `custom-protocol` の明示が必須** — tauri CLIが
   release buildで自動付与するfeatureで、これが無いとfrontendDist埋め込みで
   なくvite devサーバー `localhost:5173` を見に行く。スモーク実装中に発見)。
   対象: `dev_bridge_enabled` / `devtest_report` / `set_failure_injection`
   command、`FailureInjection`/`InjectionMode` (gento-image)、
   `set_catalog_mode` commandと仮想5万件カタログ (gento-core
   `catalog::virtual_catalog`)、stats DTOの `injection_mode`/`injection_rate`、
   `AppState::dev_bridge` / `CatalogInner::real` フィールド。
   featureは `gento-tauri` の `devtools` が `gento-core/devtools`・
   `gento-image/devtools` へ伝播 (workspaceルートCargo.tomlにコメントで設計記録)。
   `GENTO_DEV_BRIDGE` 環境変数ゲートは**devtoolsビルド内のランタイムゲート
   として残した** (計測ドライバ無変更で互換。lib.shにビルド要件のコメントのみ追加)。
2. **artifact-level証拠**: `scripts/release-smoke.sh` を新設。
   (a) featureなしreleaseバイナリからdev系識別子 (`devtest_report` /
   `set_failure_injection` / `dev_bridge_enabled` / `GENTO_DEV_BRIDGE` /
   `set_catalog_mode` / `virtual-` / `injected failure`) が不在であること
   (検出器の健全性確認用にproduction識別子の存在チェック付き)、
   (b) devtoolsビルドで起動→devtestログ→スキャン→サムネイル生成数件
   (需要駆動で6件) →graceful終了、(c) featureなしビルドがデータセットなしで
   起動し、`GENTO_DEV_BRIDGE=1` を与えてもdevtest行ゼロ・SIGTERMで正常終了。
   2026-08-30時点で全ステップPASS (証跡: `/tmp/opencode/wp0-smoke/`。
   prod-empty-ui.png = 本番UI: devボタン・オーバーレイなし・空グリッド、
   devtools-ui.png = dev UI: 仮想カタログボタン・devtestオーバーレイあり)。
   スクリプトはvite devサーバー (localhost:5173) が稼働中だと検証が汚染
   されるため起動を拒否する。
3. **DTO APIバージョン**: `gento_core::GENTO_API_VERSION = 1` を導入し
   `health` 応答に `api_version` フィールドを追加 (必須。欠如はフロントで
   error扱い)。互換方針 (major=破壊的/minor=追加) を api-contract.md §15 に記載。
4. **ディレクトリ抽象化**: `gento_core::AppDirs` (data/cache/log) を導入。
   解決はTauriアダプター (`resolve_app_dirs`、dirs crate)。
   `~/.local/share/gento-spike` (data。WP-1のSQLite DBはここへ置く予定を
   コメント・architecture.mdに明記) / `~/.cache/gento-spike` (cache) /
   `~/.cache/gento-spike/log` (log)。`--cache-dir` はサムネイルルートのみ
   上書き (後方互換。data/log位置は不変。テストで明示)。
5. **ログ・クラッシュ診断**: `GENTO_LOG` 初期化の形式
   (`TIMESTAMP LEVEL TARGET: message`, stdout) を明文化 (コードコメント+
   README)。panic hookを設定し `log_dir/panic.log` へ「panic情報 + バージョン +
   OS + APIバージョン」を追記 (既定stderrフックは維持。backtrace無しで軽量。
   実ファイル出力を単体テストで検証)。
6. **ライセンス一覧**: `scripts/gen-licenses.sh` (cargo metadata + pnpm
   licenses list + jq) → `docs/dev/licenses.md` を生成・コミット
   (Rust 475行 + npm 145行強。ヘッダに再生成コマンド明記)。
7. **crate責務の文書化**: `docs/dev/architecture.md` 新設
   (依存方向・各crate責務と公開API要点・devtools境界表・ディレクトリ・ログ)。
8. **データセットなし起動**: 既存実装が既に対応 (exists=false表示・空グリッド)。
   release-smoke (c) でreleaseビルドでも起動・生存・graceful終了を確認。
   UI側の追加修正は不要だった。
9. **フロント**: `dev_bridge_enabled` invokeの成否で `devBridgeActive` を確定し、
   仮想カタログボタン・エラー注入パネルを非表示化 (通常releaseではinvoke自体が
   rejectされるため安全なno-op)。`devtest.ts` は動的import+catchで既存どおり
   安全。`ThumbnailStats.injection_mode/rate` をoptional化 (通常releaseの
   statsに含まれないため)。

## 理由

- Codex計画レビュー指摘「artifact-level証拠」: 環境変数ランタイムゲート
  (FG-1) ではreleaseバイナリに危険commandが常駐する。featureによる
  コンパイル隔離+バイナリ検査で「存在しないこと」を証明する。
- スパイク性能シナリオ (WP-7ドライバ) はdevtoolsビルドでそのまま継続可能
  (ドライバ無変更。A6受入)。
- APIバージョン・AppDirs・panic診断はWP-1以降 (SQLite・永続カタログ) の土台。

## 残リスク / 既知の非対象

- **性能退行の詳細計測は未実施** (受入6はスモークによる簡易確認のみ:
  起動・スキャン6件・需要駆動サムネイル6件・proto p50 0.1ms。WP-7ドライバ
  での本格再計測はPM判断で実施可。スパイクのコードパス自体はゲート外のため
  退行要因は薄い。走査完了時の `inner.real = records.clone()` はdevtools
  ビルドのみで、通常releaseでは除去済み)。
- **`custom-protocol` 発見の経緯**: 当初スモークを `cargo build --release`
  (feature指定のみ) で実装していたが、このバイナリはfrontendDist埋め込みに
  ならず、偶然稼働していたvite devサーバー (第三者の `pnpm tauri dev`。
  スクリーンショット採取のために停止した) からフロントエンドを配給されて
  いた。`custom-protocol` 明示+vite不在を前提に再実施し全PASS。計測・CIで
  cargo直接ビルドを使う際はREADMEの指定コマンドを使うこと。
- `GENTO_API_VERSION` はバックエンド起動時にフロントが検証する訳ではない
  (healthの正規化で形状検証のみ。major更新時のUI分岐は実際に破壊的変更を
  行うWPで追加)。
- panic.logのI/O失敗は黙殺設計 (panic中に副次障害を起こさないため)。
- `AppDirs` の `data_dir` は現状ログ出力のみで未使用 (WP-1でDB配置に使用)。
- スモークのfallback (ctrl+F8) は今回不要だった (需要駆動で gen=6 到達)。
- licenses.mdのライセンス表記はメタ情報の転記 (法的審査ではない)。
  license宣言なしクレートは空欄。

## 次WP (WP-1: SQLite基盤) へのメモ

- DBは `AppDirs.data_dir` (`~/.local/share/gento-spike`) 直下へ。
  `resolve_app_dirs()` (src-tauri/src/lib.rs) が注入点。コアはパスを受け取るだけ。
- `GENTO_API_VERSION` を上げる場合は api-contract.md §15 の手順に従う。
- devtoolsビルドが必要な作業 (計測・5万件負荷試験) は必ず
  `--features custom-protocol,devtools` を付ける (付けないと計測commandが
  存在しない / frontendDistが埋め込まれない)。debug build (`pnpm tauri dev`)
  は常に含まれる。
- `CatalogInner.real` フィールド (仮想カタログのソース) はdevtoolsゲート内。
  WP-2の永続カタログ導入時にこのフィールドの扱いを再検討すること。
- release-smoke.shはXディスプレイとxdotoolが必要 (検証機の `:1` で動作確認済み)。
