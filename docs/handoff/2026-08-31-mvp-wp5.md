## 概要

星評価 (0-5)・採用/除外/未選別・お気に入り・タグ (作成/付与/解除/候補/削除)・
キャプション3種 (description/sd_tags/user_note) を **Asset単位 (stable
AssetId = assets.id)** で永続化し、一括編集 (確認表示付き)・Undo (直近50操作)・
高速選別モード (ビューア内 1-5/0/X/P キー + 自動次送り)・比較表示からの
採用/除外を実装した。すべて読み取り専用メタデータ面 — **元画像・ファイル
システムへは一切書き込まない** (受入条件3。除外は削除ではない)。

## 正規化規則の最終形 (確定)

`normalize_tag_name` = **trim → NFC → ASCII小文字化 → 内部空白の連続を1つの
半角空白へ圧縮** (この順で適用):

| 入力 | 正規化名 | 備考 |
|---|---|---|
| `"  Sky  "` / `"SKY"` / `" sky "` | `sky` | 前後trim+ASCII小文字化で統合 |
| `"青　空"` / `"青 空"` | `青 空` | 全角空白も空白扱い (半角1つへ) |
| `"か"+濁点(分解形)` / `"が"` | `が` | NFC正規化で統合 |
| `"ＴＡＧ"` | `ＴＡＧ` | **NFKC不適用** — 全角英字は半角と別タグ (仕様判断) |
| `"   "` | (空) | 拒否 (`Constraint`) |

`tags.normalized_name` はUNIQUE。表記違いは作成時に既存タグへ統合
(表示名`display_name`は初回登録時のまま)。LIKE検索用に `% _ \` をエスケープ。

## Undo設計

- **スコープはメタデータ操作のみ** (評価・選別・お気に入り・タグ付与/解除・
  キャプション)。**ファイル操作のUndoはWP-7で統合** (file_operations記録と
  ともに — 計画§14。本WPでは明示的に対象外)
- 実装: フロント `UndoStack` (最大50件。LIFO)。各操作の実行前にbefore値を
  捕捉した逆適用クロージャをpush (App.svelteのapplyXxx群):
  - 評価/選別/お気に入り: id毎のbefore値へ再set
  - タグ付与: 付与後に `asset_tags_list` で名前解決 → 解除
  - キャプション: 編集前の本文へ再set
- 巻き戻しはCtrl+Z (KeyDispatcherは修飾キー付きを扱わないため個別の
  capture リスナ) またはInfoPanelの「元に戻す」ボタン。redoなし (MVP)
- undo内の失敗はエントリを消費してlastErrorへ (無限再試行しない)

## asset:updated イベントと局所更新

```ts
type AssetUpdatedEvent = {
  ids: string[];      // 変更されたstable AssetId
  changes: string[];  // "rating"|"cull"|"favorite"|"tags"|"caption"
  rating?: number; triage?: string; favorite?: boolean;  // 変更後の値
};
```

- backend: 書き込みtx完了直後に (1) 表示済みカタログレコード
  (`CatalogInner.library` + Library表示中は`state.records`。`real`は触らない
  — adhoc IDの数値一致保護) をin-place更新、(2) イベントemit。
  **generation不変**のためページ再取得不要
- frontend: `patchOfEvent` → `grid.applyItemPatch` (pagerキャッシュの
  in-place更新) + フォーカス項目なら`asset_detail`再取得 + セッション集計
  再計算 (採用/除外/保留カウントがDB実値へ追従 — WP-4の足場を完成)

## 一括編集

- `asset_set_rating/cull/favorite`・`asset_tags_add` は `ids[]` 一括対応。
  repo実装は**1トランザクション** — 一部asset不在等で失敗時は全体
  ロールバック (受入条件5「編集中の異常終了でDBを不整合にしない」の
  应用: 部分適用状態を作らない)
- UI: 複数選択時、InfoPanelの各操作はまず「選択N件へ X を適用」の確認行を
  表示し、適用ボタンで実行 (誤爆防止)。キャプション編集は単一選択時のみ

## 高速選別モード (spec §9.2)

- ビューアツールバーの「高速選別」トグル (アプリ稼働中は引き継ぐ設定。
  セッション保存はWP-15の設定体系へ接続予定)
- ON中: 数字1-5=星評価・0=評価解除・X=除外・P/A=採用 → 適用後**自動次送り**
  (`viewer.nav(1)` + グリッド選択同期)。OFF中は既存ズームキー (0=fit/1=actual)
  が優先 (キー衝突の解決)。修飾キー付きは対象外 (OS操作と衝突させない)
- 適用結果はステージ右上に短く表示 (「評価 ★3」/「除外 (編集不可)」)
- Library表示 + Asset確定済み (dbState==="asset") のみ適用。それ以外は
  「編集不可」フィードバック (backendガードと二重)

## 実機E2E過程で発見・修正した副次バグ (本WP内で解決)

E2E駆動の過程で3件の実バグを発見し、本WPで修正した:

1. **InfoPanelのリアクティブ無限ループ** (captionDrafts同期effectが自分の
   書くstateを読んでいる — `captionDirty`経由): 効果フラッシュが
   `effect_update_depth_exceeded`で異常終了し、App全体のテンプレート更新が
   凍結 (グリッド需要発火せずサムネイル生成されない、summary表示が更新
   されない等)。`untrack`で依存をdetailのみに限定して解決。
   release-smokeの計測シナリオがこの凍結を検出した (gen=0でFAIL → 修正でPASS)
2. **WP-5 DTOのserde命名不一致**: TagDto/CaptionDto/AssetDetailDtoに
   `rename_all="camelCase"`を付けていたが、フロント型 (api-contract §29の
   snake_case表記) と不一致 → `tag.usage_count`がundefinedになり
   `undefined.toLocaleList()`でテンプレート描画が途中死 (タグ行より下の
   キャプション・undo・セッション欄が全滅)。snake_caseへ統一し、
   直列化形状を固定するテスト (`dtos_serialize_snake_case_matching_frontend_types`)
   を追加
3. **ハッシュ完了確定のスナップショット間引き吸い込み** (WP-2由来の潜在
   バグ): HashJobのスナップショット反映は100ms間引きだが、**最終**ハッシュ
   完了が間引き窓内に落ちると確定済みAsset (stable ID)への切り替わりが
   次のトリガまで表示へ反映されない (仮ID=編集不可のまま残留)。
   ハッシュ会計スレッドで「自分の完了でpendingが0になった」場合に
   間引きをバイパスしてスナップショットを確定反映するよう修正
   (library.rs `spawn_hash_accountant`)

またグリッドセルバッジはpagerのin-placeパッチが項目オブジェクトの同一性を
保つため、`urlFor`と同じ「gridTickを読むヘルパ経由」で評価する必要があった
(参照が同じままだとSvelteの細粒度更新が走らない — `cellBadges`ヘルパ)。

## 逸脱・判断

1. **比較表示の採用キーは K (Pではない)**: CompareViewでPは既存の
   original昇格に割り当て済み。衝突を避けK=採用とした (X=除外は
   ビューアと同一)。spec§9.4「1枚または複数枚の採用」はボタンでも可能
2. **キャプションの一括編集は非対応**: 複数選択時のキャプション適用は
   意図しない本文の上書きをするため、単一選択 (フォーカス項目) のみ。
   UIに明示表示
3. **asset:updatedに変更後の値を載せた**: 当初の「changes種別のみ」案から
   拡張 — フロントがイベント単体でセルを更新でき再取得が不要になる
4. **GENTO_API_VERSION据え置き (1)**: 追加のみ (新コマンド12・新イベント1・
   ページDTOへrating/favorite追加) で破壊的変更なしのため
5. **migration追加なし**: 既存列 (assets.rating/triage/favorite・tags・
   asset_tags・captions) で足りた (計画どおり)
6. **評価のUI表現**: 星クリックは「同じ星を再クリックで0 (評価解除)」。
   0 = 評価解除は高速選別キー (0) と同じ意味論
