## B1: walk列挙自体のキャンセル (blocker 1)

### 設計と根拠

- `gento_core::library::ScanFs::walk` に **`cancel: &AtomicBool` 引数を追加**
  (sinkの直前・`hash_and_probe` と同じ受け渡し形状)。
  - 根拠: ①sink戻り値のbool化は「処理側の中止要求」しか運べず、列挙停止を
    fs実装へ伝えるには全呼び出し地点の型変更が結局必要 ②既存の
    `cancel: &AtomicBool` 受け渡し (hash_and_probe) と同じ形でtrait内一貫性が
    保たれる ③テストdouble (FakeFs/RiggedFs/GatedScanFs) も同一の観測点を
    持てる (これがr1指摘の核心 = ゲートモデルが本番能力を仮定しない)。
- `gento_image::scan::scan_images` も同引数を追加し、**WalkDirループの各
  エントリ境界で `cancel.load(Relaxed)` を検査 → trueならbreak**。
  エントリ単位の検査は「各dirのreaddir完了/entries処理単位」より細かく、
  Relaxedロードはreaddir+statに対して無視できるコスト。
- `PlatformFs::walk` はcancelを転送。`scan_root` は既存のcancelをwalkへ渡す
  (sink内の既存チェックは二重防御として残置)。
- 副次整理: `Shared.cancel` を `Arc<AtomicBool>` → `AtomicBool` へ戻した
  (Arc化の理由だったGatedScanFs.attach経路が消滅。r1非blockerの
  「Arcは問題ない」指摘通り機能的差は無いが、根拠が消えた包装は除去)。

### テスト (本番と同一の観測点)

- **GatedScanFs再構成**: 列挙・cancel観測は本番 `PlatformFs.walk` そのもの。
  テストdoubleが注入するのは「各エントリをsinkへ手放す前にテストの解放を
  待つ」遅延のみ。cancel観測後は当該エントリを破棄し、**残りの打ち切りは
  本番walk側の境界チェック**が行う (`attach`/cancelフィールド廃止)。
- **PlatformFs実体での中断を直接検証** (`fs.rs walk_stops_enumeration_promptly_on_cancel`):
  実ファイルツリー **200 dir × 50 file = 10,000件** を生成。全走査
  `entries_walked=10000` との差分で、最初のsink呼び出しでcancelを立てた
  場合 `seen==1`・`entries_walked < 10%`・`elapsed < 5s` を表明
  (列挙tailが残らないことの直接証明)。
- `scan_images` 単位でも2件 (最初のsinkでcancel→1件で停止・事前cancel→0件)。
- **申し送り解消**: UIUX-2 handoff「即時中断は別WP」を解決済みと追記。

## B2: needsRegistrationConfirm の字句正規化先行 (blocker 2)

- `resolveLexicalSegments`: 区切り分割 → `.`除去 → `..` は直前セグメントを
  消費 (先行なし=根へ潰れる。**ドライブ文字 `C:` は `..` で消さない** —
  `C:\Users\..` → `C:\` のため)。この正規化をdepth判定の**前**に実行。
- red→green: `/home/..`・`/home/user/../..` (→`/`)・`C:\Users\..` (→`C:\`)・
  `/./home` (→`/home`) すべてtrue。`/home/user/../sub` (= `/home/sub`) 等の
  深い場合は従来どおりfalse。既存27件の挙動はすべて維持。
- doc明記: シンボリックリンク・マウントポイントは字句で捕まえられない /
  確認dialogはUX保護でbackend不変条件ではない (direct IPC素通り)。
  README・`library.ts` docに記載。

## B3: watchdogのRAII化とspin修正 (blocker 3)

- `recv_timeout` の `Err` を**Timeout/Disconnectedで区別**: Disconnected→
  即 `return` (red: 生存ルート下でsender dropすると旧実装はDB照会のbusy
  ループに入り2秒テストがtimeout)。
- **`RootLivenessWatchdog` にDrop実装** (stop送信+join)。`run_scan_root` の
  明示停止は `drop(watchdog)` へ。早期unwindでも残留しない。
- **`run_scan_all` に `ScanningGuard`** (Dropで `scanning=false` 復元)。
  red: PanicWalkFs注入でwalkがunwindすると旧実装はscanning=trueのまま
  (scan_start恒久拒否) → greenで復元。
- N3 (doc): watchdog停止のjoinはDB照会中ならbusy_timeout (最大5秒) ぶん
  遅れ得ることをdocコメントに明記 (既知・許容)。
