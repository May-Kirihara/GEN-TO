# FIXLIB-1 ハンドオフ — libraryモードでサムネイルが一切表示されない描画欠陥の修正 (2026-09-02)

実装者: implementer subagent。基盤コミット: 063a117。
**「library表示するとグリッドが全部プレースホルダーになる」(PM実機診断) —
需要計画・バックエンドは健全だったのに、フロントのレンダリング効果が
Svelte 5のキー重複エラーで永久に死んでいた描画欠陥の修正。**

## 再現と原因確定 (Phase A: devtest IM行の追加)

### 計測の追加 (apps/desktop/src/lib/devtest.ts)

`gridLines()` へセル単位の`<img>`実測行を追加 (dev bridge有効時のみ動作):

```
IM img=<セル内img総数> ok=<デコード成功> bad=<完了だが破損> pend=<ロード中>
   none=<imgを持たないセル> rdy=<ストアがURLを保持するセル>
   it=<item解決できるセル> t0=<先頭セルtitle文字数> jse=<未捕捉JS例外数>
```

- フィールド名は命名済み (`n`→`img`, `err`→`bad`): devtest行は1行結合され
  ドライバは `devtest_value <key>` を**先頭一致**で取るため、素の `n=`
  は `CL n=` (wp6のコレクション数) を、`err=` は `FO err=` をshadowする
  (実測でwp6が落ちて発見。`ok=`は他行に不存在のためそのまま)。
- あわせて `window.error` / `unhandledrejection` を捕捉し `JSE last=`
  行として露出 (WebView内例外はアプリログに出ないため)。

### 観測 (run3.sh相当・sample/dataset 1615件・実機Xephyr)

| 時点 | 修正前 | 修正後 |
|---|---|---|
| churn+3s (ハッシュ進行中) | `IM n=0 none=20 rdy=20` | `IM img=20 ok=15 pend=5 none=0` |
| final+150s (静定後) | `IM n=0 none=20 rdy=20` | `IM img=20 ok=15 pend=5 none=0` |
| グリッド領域unique colors | **201〜609** (PM実測609) | **26,246〜26,262** |
| jse (JS例外累積) | 55〜150 (`each_key_duplicate`) | 0〜1 (ResizeObserver警告のみ) |

決定的観測: **`rdy=20`(ストアは全可視セルのURL保持)なのに`n=0`(DOMにimg無し)**
——需要計画 (req/rdy) は正常、崩れはストア→描画の間。`jse`上限まで増加し
`JSE last="https://svelte.dev/e/each_key_duplicate"`。

## 根本原因

libraryカタログスナップショットはBLAKE3重複ファイルが同一Assetを共有する
(sample/datasetは1615ファイル→974アセット)。`ThumbnailGrid.svelte`の内側
keyed each `{#each cellsOf(row.index) as cell (cell.key)}` がキー=`item.id`
だったため、**同一asset idが同じ行に2セル現れるとSvelte 5は
`each_key_duplicate`を投げ、そのレンダリング効果が以後永久に更新されない**。
ハッシュ進行中はidが仮ID(file固有・一意)→安定ID(共有)へ遷移するため、
リンクが進むほど重複が生じ、ある瞬間からグリッド全体が空セルのまま固着。
adhocモードは走査idが一意のため再現しない (対照実験 run4.sh=描画OKの理由)。
スクロール/ソート変更後の需要サイクル完了後も描画されないのも、効果が
死んでいるため (probe実測: jumpMiddle/cycleSort後も`none=35 rdy=35`)。

副次発生箇所: `DevDrawer.svelte` のサムネイルイベントログ
`{#each thumbEventLog.slice(0, 8) as line (line)}` — 行内容がキーのため
同一秒・同件数のログ行で重複 (dev bridge有効時のみ、+1/sで継続)。

## 修正内容

### apps/desktop/src/lib/grid/ThumbnailGrid.svelte
セルキーを `item.id` → **`${item.id}@${index}`** (位置とidの合成) に変更。
行内一意が構造的に保証され、idが変わればセルを作り直す従来の再利用 semantics
は維持 (churn中の仮ID→安定ID切替でimgを作り直す)。

### apps/desktop/src/lib/shell/DevDrawer.svelte
イベントログのキーを行位置 (`logIndex`) に変更 (ログ行は同一内容になり得る)。

### apps/desktop/src/lib/devtest.ts
上記IM行・JSE行 (恒久計測。E2Eの偽陽性封じの観測基盤)。

### 検討したが不採用
- **img onerror+再試行**: `bad=0` (ロード失敗なし) のため不要。
- **onResetでのready mapクリア中止 (cache_generationガードへ移行)**: 今回の
  原因ではない (WP-8の設計不変)。churn中・静定後の両描画を確認済み。

### crates/バックエンド (library.rs)
`resubmit_unlinked_via_maintenance` の再エンキュー判定は**変更不要だった**:
PM観測の「enqueued=1615, merged=0 が2回」は別々のアプリ実行の**初回スキャン後
エンキュー** (12:30:17/12:36:06=2実行分。単一セッションのログに両方は無い)。
in-flight除外はプールのキーdedup (`hash:{file_id}` → `MergedExisting` で
`hash_pending`増分を即時相殺——mergedの意味はこれ)、リンク済み除外はSQLの
`asset_id IS NULL`。**保証をテストで固定**した
(`maintenance_sweep_neither_double_counts_inflight_nor_rehashes_linked`):
遅延ハッシュ中のメンテナンス周期で (a) hash_pendingが発行済み件数を超えない
(二重計上なし)、(b) リンク後3周期以上待ってもハッシュ呼び出し回数不変。

## 残リスク / 注意

- Svelte 5のレンダリング効果は例外1回でそのブロックが永久に死ぬ。今回は
  キー一意化で対処したが、**同種の「静かに固着する」欠陥の検出にはdevtestの
  `jse=`/`JSE last=`行が有効** (E2Eで`jse=0`を表明的に検証する価値あり)。
- IM行フィールドを今後追加する場合、`devtest_value`の先頭一致に注意
  (既存ドライバが消費するキー: act badge caps cf cnt cur dst edit exp fdb
  fn fv idx k kind list lock mode n ok pos r rat rn selN srt st sug tags
  tmode tot tri undo — 先頭に出す行のキーはこれらと衝突させない)。
- `pend=N` (lazy load未完了の画面外セル) は正常。`bad>0`で初めてロード失敗。
