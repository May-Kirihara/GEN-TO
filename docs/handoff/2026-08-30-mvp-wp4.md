## 概要

スパイク由来の単一グリッドUIを3ペイン製品シェル (フォルダツリー /
サムネイル一覧 / 情報パネル) へ再構成し、未登録・登録フォルダの統合閲覧、
主要操作 (OS連携含む)、クイックプレビュー、選別セッションの足場、状態表示
を実装した。仮想グリッド・ビューア・比較の性能は維持 (下記計測)。

キー割り当ては `lib/keys.ts` に一元化 (DEFAULT_KEYMAP + KeyDispatcher:
captureフェーズの単一リスナ、編集要素の入力を除外、ハンドラがfalseを返せば
後段へ流通)。Space/Enter/Esc/F2/Delete/←→を登録 (F2=リネーム・Delete=ゴミ箱
はWP-7実装予定のプレースホルダ通知。dev bridge有効時はF2が計測操作と衝突
するため無効化)。

## 新規command

| command | 概要 |
|---|---|
| `fs_list_dirs` | 任意パスの直下ディレクトリ列挙 (遅延ロード。`path:null`でホーム+/起点。隠し除外、権限エラーはerror文言) |
| `open_folder` | 閲覧フォルダ切替→一時走査開始 (dataset_path更新。不在/非ディレクトリ/権限はエラー) |
| `set_catalog_sort` | 表示ソート (name/date_desc/size_desc)。generation更新+`catalog:changed(sort_change)` |
| `reveal_in_file_manager` | OSファイルマネージャーで表示 (tauri-plugin-opener Rust API。存在検証はcommand側) |
| `open_with_default_app` | 既定アプリで開く (同上) |

既存APIへの追加 (後方互換): `get_catalog_page` 項目に
`path`/`mtimeMs`/`mimeType`/`dbState`/`triage`、`get_catalog_summary` に
`sort`、`catalog:changed` のreasonに `sort_change`。

## 永続化の方式 (判断の記録)

- **ペイン状態**: localStorage `gento:layout:v1` (左右表示・幅[160..520px
  にクランプ]・サムネイルサイズ)。`lib/ui/layout-prefs.ts`。破損時は既定値
- **前回フォルダ・ツリー展開**: localStorage `gento:folders:v1`。
  **起動時の走査対象は `--dataset` のまま** (決定論的)。前回フォルダは
  ツリーの選択ハイライトとして復元し、クリックで戻る。巨大フォルダの意図
  しない起動スキャンと計測の非決定性を避ける意図 (逸脱の明記: 受け入れ
  「閲覧位置の復元」はスクロール位置+ツリー選択で担保し、フォルダ自動オープン
  はしない)
- **スクロール位置**: 既存ScrollPositionStoreのキーをフォルダ別
  (`real:<絶対パス>` / `library` / `virtual`) へ拡張。グリッドはカタログが
  空の間scrollTopを保持できないため、total>0になった時点で復元jump
  (ThumbnailGrid内 `pendingRestore`)
- **選別セッション**: localStorage `gento:session:v1` (v:1・uuidセッション名・
  順序付きID列・位置・確認済み位置集合・origin・updatedAt。保存は400ms
  デバウンス+flush)。採用/除外の値自体はカタログ項目のtriage (DB正本) から
  集計 — セッション側には保持しない (WP-5のマーク編集と自然に合流する設計)

## 選別セッションの設計 (足場)

- 開始: 「現在の一覧で開始」= 全ページ取得の上で順序付きID列を確定 /
  「選択画像で開始」= 選択順のID列。「再開」= localStorageから復元+index再解決
- 位置は**グリッドの選択フォーカスと同期**: 選択変化→`noteFocus(id)`で
  セッション内なら位置と確認済みを更新。クイックプレビューの←→もグリッド
  選択を経由するため自動的にセッション位置が進む
- 件数表示: 確認済み=訪問位置数、採用/除外/保留=ID列のtriage集計
- 位置→カタログindexの写像 (sessionIndex) で高速化。ソート・再スキャン後は
  pagerキャッシュから遅延再構築

## 逸脱・判断

1. **前回フォルダの自動オープンをしない** (上記永続化の節参照)
2. **ライブラリ表示は登録ルート全体**: ツリーで登録済みフォルダ (配下含む) を
   選ぶと既存のライブラリカタログ (全登録ルート統合) へ切替。フォルダ単位の
   ライブラリ絞り込みはWP-8 (検索・フィルタ) で接続する。計画書§12の
   「既存source切替をUIから自然に」の解釈
3. **サムネイルサイズスライダは2段階** (小=s256/大=s512)。サイズクラスは
   backendがs256/s512/preview2048の3種のみのため。クラス追加はWP-15
4. **パスコピーの検証**: copyTextは`navigator.clipboard`→execCommand
   フォールバック+500msタイムアウト (WebKitGTKでpromiseが決定しない
   ケースの防御)。実機E2EではWMの合成入力座標の揺れが大きくメニュー項目
   クリックの自動化が不安定なため、コピー動作は単体試験で担保し、実機では
   メニュー表示とOS連携アクション実行 (新規ウィンドウ出現) を証拠とした
5. **overscan選択UIを開発パネルへ集約**: 製品toolbarからは外した
   (既定2固定。スパイクの計測用調整要素のため)
6. **`U menu=`行のdevtest追加**: dev bridgeの機械可読行にUIシェル状態
   (メニュー数・矩形・クイックプレビュー・通知) を追加。E2Eと将来の計測で
   使用
