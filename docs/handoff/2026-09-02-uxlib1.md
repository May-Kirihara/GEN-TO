# UXLIB-1 ハンドオフ — ルート登録後にライブラリが見られない操作性欠陥の修正 (2026-09-02)

実装者: implementer subagent。基盤コミット: 5940e7d。
**「登録したのに画像が表示されず、キャプションも編集できない」(PM実機診断)
—— 登録導線とライブラリ表示が接続されていなかった操作性欠陥の修正。**

## 問題 (PM診断の再現事実)

1. `addRoot()` 成功 → rootsリスト更新のみ。**カタログ表示は切り替わらない**
   (adhocのまま)
2. LibraryPanelに「ライブラリを表示」系ボタンが存在しない。library表示へ
   入る唯一の経路はツリーから登録ルート内フォルダをクリック
3. 再起動時: `--dataset`指定ならadhoc一時表示 (登録済みルートと同一パス
   でも)、無指定なら空表示——登録済み画像は出てこない
4. 編集はlibrary由来のみのため、上記2状態ではキャプション等が編集不可

## 変更内容 (apps/desktop)

### 1. 共通遷移 `showLibrary()` (App.svelte)

`selectFolder` の登録済み分岐から状態遷移を抽出 (`useSource("library")` →
`catalogSource="library"` / `activeCollection=null` / `searchActive=false` /
`gridSelection` リセット / `applySavedSort(LIBRARY_SORT_KEY)` /
`refreshSummary` + `loadPage(0)`)。利用者は4経路:

- `selectFolder` の登録済み分岐 (従来どおり。`saveFolderPrefs` はselectFolder側に残留)
- **LibraryPanel `addRoot()` 成功後の自動切替** (失敗時は `libraryError`
  表示で継続 — useSourceがfalseでも登録自体は成功しているため)
- LibraryPanelのルート行クリック (行主要部=パス+状態を包む`.roots-open`
  ボタン。有効/無効・解除は兄弟要素のため押しても行扱いにならない——
  stopPropagation不要の構造的分離)
- LibraryPanelの「ライブラリを表示」ボタン (roots-controlsへ追加。
  ルート0件でも押せる→空一覧)

起動既定表示 (後述) も同じ `showLibrary()` を使う。`exitSearch` /
`exitCollection` は現状維持 (sort適用・選択保持の挙動が異なるため統合せず。

### 2. 起動時の既定表示 — `startupCatalogView()` 純関数 (lib/library.ts)

```
datasetPath が登録ルート配下           → library起動 (重複走査・編集不可adhocの解消)
dataset 不在 (dataset_exists=false) + 登録ルートあり → library起動 (空adhocではなく)
それ以外 (存在する未登録dataset / ルート0件)        → 従来どおりadhoc (計測決定論化)
```

- `--dataset` 無指定はbackendがCWD相対の `sample/dataset` へ解決するため
  (常に入る)、「無指定」は `dataset_exists=false` で観測する
- App.svelte起動シーケンス: `catalog.init()` 後に `refreshHealth()` +
  `library.refreshRoots()` を待ってから判定 (両者の二重発行は冪等)
- ライブラリ起動時は `start_scan` をスキップ (重複走査なし)

### 3. 現仕様の案内 (breadcrumb)

library表示中のbreadcrumbに常設の小ヒント `絞り込みは検索scope` +
「ライブラリ (登録ルート全体)」のtooltip (フォルダー絞り込みは検索scopeで
可能、の一言)。PMの「一時表示」に対し、catalog通知経由はcatalog.onChangeで
毎回上書きされるため**常設表示**で代替 (意図の充足優先。report参照)。

### 4. 編集不可の理由 — `editLockedReason()` (lib/metadata.ts)

`canEditMetadata` と同一規則で理由文案を返す純関数。InfoPanelの編集
セクション (`{:else if !canEdit}` のプレースホルダー) が使用:

- `!libraryBacked` →「※未登録フォルダ——ルート登録すると編集できます」
- `dbState=provisional` →「※ハッシュ計算待ち——確定後に編集できます」
- 選択なし=従来の「画像を選択すると編集できます」のまま

### 5. dev bridge (lib/devtest.ts)

- M行へ `lock=` 追加 (`h`=ハッシュ待ち / `u`=未登録フォルダ / `-`=その他)
  —— InfoPanel理由文案の機械検証用
- foCmdMode (ctrl+shift+F12) に `1`=`foShowLibraryRow` (行切替ボタンclick) /
  `2`=`foShowLibraryBtn` (「ライブラリを表示」click) を追加 (数字の空き枠)

## 設計判断の記録

- **案内を一時noticeでなく常設ヒントにした理由**: `folderNotice` は
  catalog.onChangeで毎回クリアされ、libraryストアのnotifyも
  `overlapWarning ?? lastNotice` で上書きされる。遷移のたび消える一時表示
  よりbreadcrumb付近の常設小ヒント+tooltipの方が確実に届く。
- **起動ライブラリ判定をfrontendに置いた理由**: `--dataset` は常に
  backendで解決済みパスがhealthから得られ、登録ルート一覧も既存commandで
  取れるため backend変更不要 (crates無変更)。
- **library起動時に `saveFolderPrefs` しない理由**: 起動直後はツリー展開
  復元が並行しており、expanded=[] で上書きする競合を避ける (selectFolder
  経由の遷移では従来どおり保存)。
