## 何を作ったか

選択/コレクションを入力に、画像コピー + 同名`.txt`のSD学習データセットを
ユーザー指定dirへ書き出す。dry-run (export_preview) → 確認 → 実行
(export_execute) の2段。cancel・manifest・部分失敗対応。**元ファイル・DBは
完全不変** (ソースは `open_regular_beneath` の読み取り専用open、DBは
`with_reader` のみ = query_onlyで書き込みSQL構造拒否)。

### 配置判断 (PM「fat問わず判断して報告」への回答)

`export.rs` は **tauri crateに置いた**。理由: (1) 書き込みDB状態が一切不要
(gento-dbに置いたWP-13 backupと違い、repo読み取りのみで成立)、(2) 既存
pubヘルパ (`gento_platform::rename_noreplace` / `gento_core::
open_regular_beneath` / `rfc3339_after_now`) の組み合わせで足りて新crateが
不要、(3) fileops.rs (plan/execute/cancel + Mutex排他 + AtomicBoolキャンセル
+ Host trait進捗) と同一のアプリケーション層パターン。**新規依存なし**
(dependency-notes.md の記載不要を確認)。

### PM決定事項の実装メモと仮定記録

1. **代表file = present最小file id** (全file最小ではない): 移動で旧経路が
   missingになった直後でも実在複製へフォールバックするための精緻化。
   決定論は維持 (DB状態からの純関数)。
2. **caption優先順は `sd_tags` 現行 → `description` 現行 → タグ列**。
   PM指示は「現行captionがあれば本文」でkindが未指定のため、SD用途特化の
   kindを先頭にする解釈を採った。**反証条件: ユーザーがkind選択UIを求めた
   場合**はオプション化が必要。
3. **タグ列順序** = `list_asset_tags` 契約どおり `normalized_name ASC`
   (display_nameを", "結合)。並べ替えUIはMVPに無し (PM決定どおり)。
4. **既存出力との比較の正本はソース実体** (開いたfdのBLAKE3) であって
   DBの content_hash ではない。スキャン後の元ファイル変化があっても
   「出力済み判定」が実体ベースで冪等になる。
5. **manifest (`export-manifest.json`) は再実行で置換する** (tmp→sync→
   原子rename。NOREPLACEではなく通常rename)。自身の成果物であり最新runの
   記録を残すため。ユーザーファイル無断上書き規約の対象外と明記 (§48)。
6. **衝突suffixの割当は「本run内の使用名集合」のみ考慮**: 出力先に既に
   `img-1.png` が存在しても割当に影響しない (既存はidentical/conflict分類で
   処理)。これが「同じ設定の再実行結果が予測可能」(受入条件) の実装手段。

### 既知の逸脱・簡易対応

- **キャンセルはper-item境界**: 1項目 (コピー+txt) の途中では中断しない。
  PM決定どおり。
- **tmpファイルのクラッシュ残骸**: 出力先が登録ルート外の場合、起動時掃除
  (fileops) の対象外。tmp名はfileops厳密形式のため、ルート内なら掃除される。
  ルート外はdotfileとして残り得る (manifestには出ない) — 許容判断。
- **preserve構造の中間ディレクトリは項目失敗時に残り得る** (空dir削除は
  実装しない — 再実行で再利用されるため無害)。
- **出力先が登録ルート内でも警告しない** (ユーザー責任。スキャンで拾われる
  が書き込み不変規約には抵触しない)。
- **NAME_MAX**: 255byte超のdisplay_nameにsuffix/tmp接尾が付くと書込失敗
  (Failed entryとしてmanifest記録)。 filename長の事前検査は未実装。
- **`file_ops_cancel` と同じく cancel は「次の項目境界」で効く**。
  実行前の誤クリックは無害 (実行開始時にflagリセット)。
