### A. darwinクロスチェック

- **E0617修正** (`path_safety.rs` `create_exclusive_at`):
  `0o644 as libc::mode_t` → `0o644 as libc::c_uint`。darwinのmode_tは
  u16でvariadicに渡せない (Linuxのmode_t=u32=c_uintと一致するため
  両platformで正しい)。
- **緑化**: gento-core / gento-platform / gento-search の3 crateが
  `cargo check --target aarch64-apple-darwin` 緑。
- **環境限界 (検出したクロス欠陥の全体像)**:
  - gento-tauri: `objc2-exception-helper` がObjective-C (`try_catch.m`)
    をccでコンパイルするためLinuxホストでは不可 (Rust欠陥ではなく
    Cツールチェーン要件)
  - gento-db: `libsqlite3-sys` (bundled C) + `blake3` NEON C
  - gento-ai: `blake3` NEON C / gento-image: `dav1d-sys` C + blake3
  - gento-embedding: `aws-lc-sys` C + `link-cplusplus`/`usearch` C++
  - E0617以外にRustレベルのクロス欠陥は発見されず (緑3 crate)。
    上位5 crateは依存build scriptが先に失敗するため到達不能 —
    実機checkはWP-18前の残課題 (platform-notes §1.1)。
- **検査で発見した実行時欠陥 (未修正・文書化)**: macOSでプロトコルの
  キャッシュ系readが `/proc/self/fd/{fd}` 依存で常に失敗する
  (`protocol.rs` `read_file_checked`。元画像配信は無影響)。
  darwin向け修正方針 (`fcntl(F_GETPATH)`) はplatform-notes §3.1に記録。
  コンパイル検証なしにunsafeを書くことを避けたため実機フェーズ対応。

### B. path_safetyのプラットフォーム網羅

- **Windows字句fallback実装**: `is_lexically_beneath(path, root)` を
  純関数 (cfg外・全platformコンパイル) として実装 — `\\?\` /
  `\\?\UNC\` 前置の透過的除去、ドライブ文字・UNC server/share の完全
  一致、大文字小文字同一視、区切り`\`/`/`両対応、`.`除去と`..`の字句
  解決。`cfg(windows)` のwalk内で `canonicalize` 結果の包含検証として
  使用。**テストはLinux上で実証** (`\\?\C:\` 形式含む4テスト。
  ドライブ不一致・UNC不一致・成分境界・`..`脱出の拒否を含む)。
- **macOS fd-walk接続確認**: `openat2` はlinux cfgのためmacOSでは常に
  fd歩行に落ちる。既存テスト `intermediate_symlink_directory_is_not_
  traversed` が公開APIと歩行関数の双方を検証しており、macOS経路
  (=歩行のみ) の保護を接続確認 (コメントで明記)。
- **境界ドキュメント**: api-contract §47 にプラットフォーム別保護手段
  の対応表を追加 (Linux openat2=構造的 / 旧カーネル+macOS fd歩行=構造的 /
  Windows字句=best-effort・TOCTOU窓あり)。
- **制限の明文化**: platform-notes §2.1-2.2 (TOCTOU耐性無し・8.3短縮名
  /ADS非解釈)。

### C. fileops copy_file の never-unlink (FG-WP16-6申し送り解消)

- `File::create(tmp)` → **排他 `create_new`**、失敗cleanup unlink 3箇所

- **red→green実証**:
  - red: 既存2テストの契約更新 (衝突時tmp残留許容・キャンセル時tmp残留

### D. scrubの非ASCII・Windowsパス対応 (WP-15/16申し送り解消)

- **政策決定 (過剰scrub側に倒す安全側)**: パス候補に**直接連結**する

  パス候補に連結しない通常文の非ASCII (`スキャン完了: 3件` 等) は無傷。
- red→green: `scrub_paths_covers_non_ascii_path_components`

  `scrub_paths_leaves_non_ascii_prose_alone` (過剰側のガード)。
- api-contract §49 の限界記述を更新 (旧限界①を解消済みに書き換え、

### E. platform差のgento-platform隔離 (§25受け入れ条件)

- **移動 (実利のあるもののみ)**:

## 残課題・申し送り

1. **darwin実機 (またはosxcross導入) での`cargo check --workspace`**:
   C依存5 crateのRustレベルクロス欠陥は本環境では検出不能
   (platform-notes §1.1)。
2. **macOSプロトコルキャッシュreadの`/proc`依存**: 実行時欠陃として
   発見・文書化済みだが未修正 (darwin check不可のため)。修正方針は
   platform-notes §3.1 (`fcntl(F_GETPATH)`)。
3. **Windows実機検証**: 本WPは「検査+純関数テスト」のみが手段という
   制約を文書化。WebView2・ゴミ箱・keyring・長いパス・ドライブ境界は
   実機フェーズ (計画書§25 Windows項目)。
4. **Windows file ID提供** (`os_file_id_of` が非unixでNone): トークン
   同一性検証がsize+mtimeのみ。WP-18以降。
5. **パスのUTF-16ネイティブ保持** (gento-db encode_path): lossy変換の
   既知制限として明文化。DB schema変更を要するため見送り。
