## D1: 全migrationの新規DB+旧fixture検証

- migrationは**9件** (v1 initial_12tables … v9 wp11_embedding_jobs_app_settings。
  `crates/gento-db/src/schema.rs` の MIGRATIONS)。
- 新規テスト `every_stage_fixture_upgrades_to_latest_with_data_retention`:
  段階 n=1..=8 の各DBを `MIGRATIONS[..n]` で構築し、段階のCHECK制約に適合する
  代表データ (library_roots/assets×2/files×2/tags/asset_tags/captions/
  collections+items/asset_metadata/embeddings/jobs/file_operations×2/
  ai_profiles+ai_runs) を投入 → 全migrationをbackup_dir付きで適用し、
  (a) 適用成功 (applied = n+1..=9) (b) データ保持を**段階awareな意味的等価**で
  検証:
  - 段階<=4の `file_operations.status` は#5の文書化マッピング
    (pending→executing / succeeded→done) が等価の定義
  - `files.mtime_ns` は段階>=4投入値を保持・それ以前はNULL (次走査で充填)
  - jobsは#8フィルタで存続する行のみ投入 (破棄側の意味は既存
    `v7_populated_jobs_migrate_to_v8_with_legacy_and_duplicate_rows` が正本)
  - backupが必ず作成され、単独で開ける段階nのスナップショットであること
  - `PRAGMA foreign_key_check` 0件・`integrity_check` ok
- `stage8_fixture_is_noop_at_latest_and_retains_data`: 最新段階は再実行で
  適用列空・backup無し・データ不変 (アップグレード経路の終端)。
- productionコード・migration定義は**不変** (テストのみ追加)。
  fixtureはテスト内で段階適用により構築 (repoにfixtureファイルなし)。

## D3: バックアップ復元演習 (実機E2E)

`scripts/wp18_backup_restore_drill.sh` (uxlib1流儀・Xephyr :6・HOME/`--db`/
`--cache-dir`隔離・release+devtools build・GENTO_DEV_BRIDGE=1)。

**実行結果: 13 PASS / 0 FAIL** (2026-09-04):

```
P1: ルート追加→library表示 / ハッシュ後編集可 / ★5付与 / タグ付与 (tags=1)
P2: .gento作成 (ba=4 bf=4 bc=0) + backup-info.json complete=true
P3: SIGTERM graceful終了 / DB+キャッシュ削除でバックアップ残存
P4: 新規DB再登録 → 復元前は評価/タグ無し (rat=0 tags=0 — 消失実証)
P5: 復元実行 (bap=4 bsk=0)
P6: 再起動後 ★5復元 (rat=5) / タグ復元 (tags=1) / graceful終了
```

- バックアップ作成・復元とも**生産command** (`backup_portable_create` /
  `backup_restore_plan` + `backup_restore_execute`。BackupDialog/RestoreDialog
  と同一のinvoke列) をdev bridge (foCmdMode `6`/`7`・BK行) から駆動。
- スクリーンショット4枚: `/tmp/opencode/wp18/drill/shots/` (作業領域・再実行で
  再生成可能)。
- **機械的に再現できない部分の手順書** (アンインストール相当の範囲注記):
  実パッケージ (deb/rpm/AppImage) のアンインストール操作自体 (dpkg/rpm remove・
  デスクトップエントリ削除) はE2E化していない。本演習は「アンインストールに
  より失われるのはアプリ本体だけであり、ユーザーデータ (DB) の消失のみが
  評価・タグを失う」ことをDB削除で等価再現した。パッケージ削除後の
  `~/.local/share/gento-spike/` 残存確認は release-checklist §3.4 の
  手動ゲートに組み込み済み。
- 起動方法の注意: Xephyrのホスト画面は `HOST_DISPLAY` (既定 :0) —
  スクリプト内で明示的に分離済み (DISPLAY変数のexport伝播に注意)。
