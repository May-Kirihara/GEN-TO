# WP-11 ハンドオフ: Phase A (モデル配布源確認) で blocked

- 日付: 2026-09-02

- 状態: **blocked**（コード変更なし。基盤コミット 477a839 のまま）
- 判断必要者: ユーザー（PM）

## 結論

**`cl-nagoya/ruri-v3-70m` / `cl-nagoya/ruri-v3-30m` ともに公式ONNXファイルが存在しない。**
WP指示「公式ONNXが存在しない場合、その時点で停止してPMへ報告（変換はユーザー判断が必要:
HF管理リポジトリの作成有無）」に従い、実装開始前に停止した。

これは設計正本 docs/embedding-runtime.md §3 の前提との不整合である:

> ruri-v3公式モデルを再現可能な手順でONNXへ変換し、元モデルとの出力誤差を検証した成果物を
> GEN-TO管理のHugging Faceリポジトリから配布する。

設計が想定する「GEN-TO管理のONNX配布物」がまだ存在せず、その作成（変換+出力検証+置き場所）が
本WPの前提として必要になる。変換はアプリ同梱を禁止されたPython/PyTorch/SentenceTransformersを
ビルド時ツールとして使う作業であり、「どの変換成果物をどこで配布するか」はユーザー判断事項。

### 推論設定（manifestに記録すべき値の出典）

- **pooling**: 1_Pooling/config.json = `pooling_mode_mean_tokens: true`（cls/max/weightedmean/lasttoken
  すべて false）。attention mask考慮のmean pooling——embedding-runtime §6の想定と一致
- **最大長**: sentence_bert_config.json = `max_seq_length: 8192`（config.json の
  max_position_embeddings=8192 と一致。アプリ側の採用上限はmanifestで短く固定予定）
- **正規化**: READMEのusage例が `torch.nn.functional F.normalize(p=2, dim=1)` を適用（L2正規化）
- **query/doc接頭辞** (README「1+3 prefix scheme」より原文確認済み):
  - `""`（空）: 意味エンコーディング用
  - `"トピック: "`: 分類・クラスタリング用
  - `"検索クエリ: "`: 検索クエリ用 ← 我々のquery接頭辞
  - `"検索文書: "`: 検索文書用 ← 我々のdoc接頭辞

## 必要なユーザー判断

**A案（設計どおり・推奨）**: GEN-TO管理のONNX配布物を作る
- 変換: ビルド環境で一度だけ Python + PyTorch + Transformers (>=4.48) + SentenceTransformers で
  変換スクリプトを実行（アプリには同梱しない——設計§1の禁止は「アプリへ同梱」であり、
  ビルド時ツール使用は矛盾しない）
- 検証: 公式SentenceTransformers出力との誤差比較を自動化（計画§19の要件）
- 配布: (a) GEN-TO管理HFリポジトリ、または (b) アプリ配布物への同梱/自前配信のいずれか要決定
- manifests/checksumはWP指示どおりアプリ側定数化

**B案（設計改訂が必要）**: 第三者ONNX変換を利用
- 設計§3「第三者が変換したONNXモデルへ初期状態で依存しない」に反するため、
  embedding-runtime.md の改訂（ユーザー判断）が前提。出力誤差・保守性の保証が弱い

**C案（非推奨）**: アプリ内変換——設計§1がPython等のアプリ同梱を明示禁止しており不可
