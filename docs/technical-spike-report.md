## 2. 検証の目的と範囲

技術検証計画が定義した高リスク経路（走査→情報取得→サムネイル生成・キャッシュ→プロトコル配信→仮想グリッド→単一/比較表示）を、実データセットと5万件仮想カタログで実測し、採用予定技術構成の正式決定に必要な証拠を得る。完了版SQLite・AI・タグ・ファイル操作・JPEG等複数形式・他OSは対象外（実装計画§18）。

## 3. 実装の概要

```text
GEN-TO/
├── crates/gento-core    # ドメイン型・カタログ・ページング・優先度 (Tauri非依存)
├── crates/gento-image   # 走査・PNG probe・生成・キャッシュ・ワーカープール (Tauri非依存)
└── apps/desktop         # Svelte 5 + TS UI / src-tauri (薄いTauriアダプター: command・event・3プロトコル)
```

- 仮想化: TanStack Virtual公式Svelteアダプタ (`@tanstack/svelte-virtual` 3.13.36)。判断ゲートAは第1候補で通過（Svelte 5対応を確認、命令的DOMへの降格不要）
- サムネイル: `image`デコード（Limits付き）→ 拡大しないリサイズ → lossy WebP q80（`webp` crate、明示的RGBA渡し）
- キャッシュ: Xxh3-128キー (パス+サイズ+mtime+クラス+アルゴリズム版)、256分桶、一時ファイル→fsync→rename、**2GiB上限**（書き込み前予約制の会計、95%までLRU退避、実行中保護）
- ワーカープール: 固定4ワーカー、優先度5段（Interactive > Viewport > Prefetch > Overscan > Background）、同キューdedup、未開始キャンセル+実行中協調キャンセル、panic隔離、一時停止/再開
- プロトコル3種: `gento-thumb://` `gento-preview://` `gento-original://` — AssetId→登録レジストリ経由のみで解決（URLをパスとして解釈しない）、O_NOFOLLOW+fd包含検証によるTOCTOU対策、内容依存URL version
- 規模: 約21,000行追加、10コミット、Rust 159 / vitest 218テスト

## 5. 技術的知見

### 採用技術の評価
- **Tauri 2 + WebKitGTK**: カスタムプロトコルは`scheme://localhost/`形式で到着し、トラバーサルauthorityはWebKitが正規化して渡す（拒否側で処理可能）。SIGTERMはself-pipe+`app.exit(0)`のgraceful実装が必須。起動1.76sの大半はGTK/WebKit初期化で、アプリ論理は十分高速
- **Svelte 5**: `$state`はクラスインスタンスを深くプロキシしない——プレーンクラスストアは`onChange`→ローカル`$state`同期、`{#each}`内のフィールド読みは浅い複製が必要（WP-2/WP-6で実バグとして顕在化、パターン化して解決）
- **TanStack Virtual**: SvelteアダプタがSvelte 5でそのまま動作。`setOptions`の`estimateSize`変更は測定キャッシュへ反映されないためセルサイズ変更はコンポーネント再生成で対応
- **WebP (lossy q80)**: 生成コスト・容量ともに問題なし (p50 20ms/枚、1.8%)。**性能問題が観測されなかったためJPEG等との比較計測は未実施**（計画の比較ゲートは不発火。次段階課題）
- **Tauri IPC**: 応答がまれに喪失することがある——フロント側のin-flight管理にタイムアウト必須（実機で恒久ストールとして顕在化し修正）

### スパイク固有の計測インフラ知見
- WebKitGTKはlongtask未対応 → rAF基準のlong frameで実測
- 共有デスクトップではxdotoolポインタが外部操作に上書きされる → キーボード (XTest) + 開発限定DOMイベントブリッジ (`GENTO_DEV_BRIDGE=1`) の組み合わせが安定
- 上記ブリッジにより10シナリオ×3走をrelease buildで自動計測し、ログ・統計をリポジトリに保全 (`docs/dev/measurements/`)

**PASS（Linux開発機における技術採用合格）**
